# ElyHarn 多 Session 固定提示词管理需求

## 1. 文档定位

本文定义一个供人使用的 ElyHarn Web 管理页面，用来统一查看和编辑主意识、潜意识中枢、记忆潜意识等 Session 的固定提示词。

交互参考 Coopanion 的“系统提示词”页面，但后端语义必须服从 ElyHarn 的真实装配方式，不能照搬其“重载前缀”“清空对话”等操作。

本轮只确定需求，不实现页面，不修改线上提示词。

## 2. 已核实的现状

### 2.1 固定提示词如何生效

ElyHarn 当前通过 `@elysia/conscious-mind/standing-prompts` 装配固定提示词：

1. 每个 Agent 作用域登记一个有顺序的文件列表、必需文件列表和 `baseDir`。
2. 每次组装模型请求时重新读取文件，而不是只在 Session 创建时读取一次。
3. 每个非空文件先执行 `trim()`，再用一个空行，即 `\n\n`，按配置顺序连接。
4. 必需文件缺失或内容为空会中止装配；可选文件缺失或为空会被跳过。
5. 当前固定提示词使用 `interpolate: false`，没有 Coopanion 的 `{{variable}}` 模板变量语义。
6. 当前时间属于每轮注入的用户消息，不属于固定提示词文件，不能混入固定提示词编辑器。
7. 主意识还可能通过 `elysia/main-prompt-addon` 追加动态内容；这类内容必须与文件正文分开标识。

因此，ElyHarn 不需要“保存后重载前缀”：**保存写入文件后，之后新发起的模型请求自然会读取新版本。**

### 2.2 首版 Session 与文件注册表

首版只纳入以下三个现有 Session。页面必须读取同一份服务端注册表，不能在前端另写一套文件列表。

| Session | Session ID | 当前有效文件顺序 | 必需文件 |
| --- | --- | --- | --- |
| 主意识 | `elysia-conscious-mind` | `SOUL.md`、`USER.md`、`MEMORY.md`、`CONSCIOUS-MIND.md` | `SOUL.md` |
| 潜意识中枢 | `elysia-subconscious-router` | `SOUL.md`、`USER.md`、`MEMORY.md`、`SUBCONSCIOUS-ROUTER.md` | `SOUL.md`、`SUBCONSCIOUS-ROUTER.md` |
| 记忆潜意识 | `elysia-subconscious-memory` | `SOUL.md`、`USER.md`、`SUBCONSCIOUS-MEMORY.md` | `SOUL.md`、`SUBCONSCIOUS-MEMORY.md` |

注意：Web 有效配置中的记忆潜意识当前不装配 `MEMORY.md`，虽然潜意识插件的代码默认值曾包含它。管理页面必须以实际生效配置为准，不能凭插件默认值猜测。

实时通话、直播和其他 Session 暂不进入首版；以后只能通过显式注册加入，不能因为扫描到某个 Markdown 文件就自动开放。

### 2.3 共享文件是核心约束

三个 Session 当前从同一个提示词目录读取文件：

- `SOUL.md` 被三个 Session 共享；
- `USER.md` 被三个 Session 共享；
- `MEMORY.md` 当前被主意识和潜意识中枢共享；
- 各 Session 的专属文件只影响对应 Session。

所以“在主意识页面保存 `SOUL.md`”同时也是在修改潜意识中枢和记忆潜意识。界面必须在编辑前、保存前和保存后都明确表现这一影响范围。

## 3. 参考界面：保留什么，不搬什么

### 3.1 保留的交互

参考 Coopanion，保留以下已经被证明方便的设计：

- 按块展示提示词，每块有标题、文件名、职责说明和可编辑／只读标记；
- 块可折叠，支持全部展开／全部收起；
- 编辑器支持撤销、重做、`Ctrl+S`／`Cmd+S` 保存；
- 显示未保存状态、正在保存、保存成功和保存失败；
- 支持放弃当前块修改、放弃全部未保存修改；
- 显示块数和估算 token 数；
- 自动生成内容只读；
- 提供按真实顺序连接的完整预览；
- 页面离开前拦截未保存修改。

### 3.2 不照搬的部分

- **不引入变量面板。** ElyHarn 当前不做模板插值，显示 `{{variable}}` 会制造错误认知。
- **不设置“立即应用”按钮。** 保存之后的新请求会自然读取文件，没有单独重载步骤。
- **不把“清空对话并重开”放进保存流程。** 固定提示词修改不需要删除任何 Session 历史。
- **不假装完整预览等于整次模型请求。** 消息历史、工具 Schema、时间消息等不在固定提示词预览中。
- **首版只参考交互，不直接复制 Coopanion 代码。** 若以后需要复用其实现，必须另行核对 AGPL-3.0-or-later 的适用条件。

## 4. 目标与非目标

### 4.1 首版目标

1. 在一个 Web 页面切换并管理多个 ElyHarn Session。
2. 让人清楚看到每个 Session 实际使用哪些文件、顺序和必需关系。
3. 对共享文件给出明确提示，避免误改其他 Session。
4. 提供稳定的分块编辑、撤销、差异检查、完整预览和安全保存。
5. 防止并发页面、模型文件工具或人工修改被静默覆盖。
6. 保存前备份，保存后可以从维护入口追溯操作。
7. 不重启 ElyHarn，不清空 Session，就能让后续新请求使用新内容。

### 4.2 非目标

- 不做桌宠客户端内置编辑器；该页面属于 ElyHarn Web，与桌宠解耦。
- 不开放任意路径文件管理。
- 不让爱莉通过模型工具调用这个管理接口。
- 不编辑模型配置、渠道配置、API Key、DSH 管理令牌或其他凭证。
- 不做提示词自动优化、自动改写或质量评分。
- 不做持久草稿、多人协同、完整版本分支和自动回滚策略。
- 不通过清空对话来解决提示词生效问题。

## 5. 页面结构与交互

### 5.1 Session 选择区

页面顶部或左侧提供 Session 选择器，至少展示：

- 中文名称；
- 稳定 Session ID；
- 固定提示词块数；
- 当前是否有未保存修改；
- 当前是否存在读取或装配错误。

切换 Session 时不得丢弃其他 Session 的未保存草稿。若同一个共享文件在多个 Session 中可见，它们必须指向同一份前端草稿，不能各自保存一份互相矛盾的文本。

### 5.2 分块编辑区

每个文件块展示：

- 中文标题与职责说明；
- 文件名；
- 在固定提示词中的顺序；
- `必需`／`可选`；
- `可编辑`／`只读`；
- `共享`标记及受影响 Session；
- 文件缺失、为空、外部已修改等状态；
- 当前字符数、UTF-8 字节数和估算 token 数。

编辑器要求：

- 保留换行，不自动改写 Markdown；
- 支持撤销、重做、折叠、逐块放弃修改；
- 必需文件为空时，在保存前给出明确错误；
- 可选文件允许为空，并在预览中表现“此块将被跳过”；
- 不允许通过界面修改文件顺序、文件名或必需关系；这些属于部署配置，不属于正文编辑。

### 5.3 工具栏

首版包含：

- 全部展开／全部收起；
- 撤销、重做；
- 放弃全部修改；
- 查看差异；
- 保存修改；
- 刷新磁盘状态。

状态文案必须区分：

- `有未保存修改`；
- `正在保存`；
- `已保存，之后新发起的模型请求将读取此版本`；
- `磁盘文件已被其他入口修改，需要处理冲突`；
- `保存失败，磁盘版本未被主动覆盖`。

“保存成功”只表示文件已经安全写入，不表示某个正在运行的模型已经看过它。

### 5.4 差异预览

保存前可以查看每个脏块的差异：

- 左侧为打开页面时的磁盘基线；
- 右侧为当前草稿；
- 若磁盘已被外部修改，另显示当前磁盘版本，不允许仍拿旧基线冒充现状；
- 共享文件在差异标题中列出全部受影响 Session。

首版使用文本差异即可，不要求复杂的字符级高亮。

### 5.5 完整固定提示词预览

提供两种明确标识的视图：

1. **当前草稿预览**：使用尚未保存的编辑内容，标题必须写明“草稿，尚未生效”。
2. **已保存版本预览**：重新从服务端读取磁盘内容，不使用浏览器缓存冒充。

两种视图都必须复用与 `loadStandingPrompt` 一致的规则：逐块 `trim()`、跳过可选空块、必需空块报错、按顺序用 `\n\n` 连接。

动态 Skill 列表或其他 `main-prompt-addon` 内容若被展示，必须作为“运行时动态段”单独只读展示，并注明它可能随环境变化。不能把这些内容写回 Markdown 文件，也不能把当前时间消息拼进固定提示词。

token 数只能标为“估算”，不能暗示等于具体模型的精确计费 token。

## 6. 草稿、保存与生效状态机

### 6.1 首版不引入独立持久草稿

首版的“草稿”只是浏览器中的未保存编辑状态：

- 编辑不会写磁盘；
- 保存就是写入正式文件；
- 没有第二套需要另行“应用”的服务端草稿；
- 刷新或离开页面前必须提示未保存内容；
- 浏览器崩溃后的草稿恢复不属于首版。

这样可以避免“保存了但没应用”和“应用了但不知道写到哪里”的双状态歧义。

### 6.2 单文件状态

```text
干净 clean
  └─ 用户编辑 → 未保存 dirty
                   ├─ 放弃修改 → clean
                   └─ 保存 → 保存中 saving
                                ├─ 成功 → clean，更新 revision
                                ├─ 冲突 → conflict，保留草稿
                                └─ 其他失败 → dirty，保留草稿和错误
```

外部刷新不能覆盖 dirty 或 conflict 中的草稿。

### 6.3 生效边界

保存成功后：

- 已经发给模型服务的请求不被追溯修改；
- 之后新发起的模型请求在装配时重新读取文件，因此使用保存后的内容；
- 如果当前轮次之后还会发起新的工具步骤请求，那些新请求也可能读到新版本；
- 不重启 ElyHarn；
- 不清空或重建 Session；
- 不承诺已经生成的回答会改变。

界面统一使用“之后新发起的模型请求”，不要笼统写成“立即影响当前回答”或“下一轮必定生效”。

## 7. 服务端注册表与数据模型

### 7.1 注册表是唯一事实来源

服务端从实际 ElyHarn 配置建立 Session 与文件注册表，至少包含：

```ts
interface PromptSession {
  sessionId: string
  title: string
  blocks: PromptBlockRef[]
}

interface PromptBlockRef {
  fileId: string          // 稳定的注册表 ID，不是客户端提交的路径
  fileName: string
  title: string
  description: string
  order: number
  required: boolean
  editable: boolean
}

interface PromptFile {
  fileId: string
  content: string
  revision: string        // 对磁盘原始字节计算的安全哈希
  exists: boolean
  emptyAfterTrim: boolean
  byteLength: number
  affectedSessionIds: string[]
}
```

首版文件均来自同一目录，但 API 仍使用 `fileId`，不能为了当前实现简单而让客户端提交任意路径。

如果以后不同 Session 使用不同 `baseDir`，相同文件名也不能再被当成同一个 `fileId`。

### 7.2 只读动态段

动态段使用独立类型，不与文件块混用：

```ts
interface GeneratedPromptSegment {
  key: string
  title: string
  content: string
  editable: false
  volatile: true
  note: string
}
```

首版如果无法可靠取得某段动态内容，应显示“由运行时生成，本页不展开”，不能伪造一个静态版本。

## 8. 保存、并发、备份与审计

### 8.1 保存请求

一次保存可以包含当前 Session 的多个脏块，但同一个共享文件只能出现一次。

```ts
interface SavePromptChanges {
  sessionId: string
  changes: Array<{
    fileId: string
    content: string
    baseRevision: string
  }>
}
```

服务端必须重新验证每个 `fileId` 是否属于当前注册表以及该 Session，不能相信客户端传入的名称、路径、必需属性或影响范围。

### 8.2 保存顺序

一次保存按以下顺序执行：

1. 读取所有目标文件的当前版本；
2. 检查全部 `baseRevision`，任一冲突则整批不写；
3. 校验所有新正文，包括必需非空、UTF-8 字节上限和注册表权限；
4. 为所有即将修改的现有文件创建维护备份；
5. 通过同目录临时文件和原子重命名逐个写入；
6. 返回新的 `revision`、保存时间和全部受影响 Session。

如果写入阶段发生部分失败，必须尝试用已备份内容恢复本批已写文件，并明确报告恢复是否成功。不能返回一个看似全部成功的结果。

### 8.3 并发冲突

- `revision` 必须来自磁盘原始内容，而不是编辑器显示文本；
- 任何入口造成的内容变化都应使旧 `baseRevision` 失效；
- 冲突响应返回目标文件当前 `revision`，并允许界面读取当前正文做三方比较；
- 冲突时保留用户草稿，不自动合并，不强制覆盖；
- “强制覆盖”不属于首版。

### 8.4 复用现有保护机制

现有 `file-capabilities` 已有必需非空、单文件字节上限、写入前备份、备份保留和模型路径隔离规则。实现管理后端时应抽取并复用共同校验／备份能力，避免维护两套不同规则。

统一管理入口还需要自己的维护审计记录，记录：

- 时间；
- 操作者身份；
- `fileId`；
- 修改前后 `revision`；
- 备份标识；
- 成功、冲突、失败或恢复结果；
- 受影响 Session。

审计不记录 API Key 等无关敏感信息，也不能放在模型可写工作区。

## 9. API 契约与错误语义

以下为需求级契约，实际路由可服从 DSH Web 的既有约定。

### 9.1 读取

```text
GET /api/elysia/prompts/sessions
GET /api/elysia/prompts/sessions/{sessionId}
```

返回 Session 注册信息、有序文件块、每个文件的 `revision`、共享影响和只读动态段说明。

### 9.2 预览

```text
POST /api/elysia/prompts/preview
```

输入 `sessionId` 与可选的草稿修改，返回按真实规则连接的预览、跳过块、校验错误和估算 token。该接口绝不写文件。

### 9.3 保存

```text
PUT /api/elysia/prompts
```

输入 `SavePromptChanges`，返回：

```ts
interface SavePromptResult {
  savedAt: string
  files: Array<{
    fileId: string
    revision: string
    backupId?: string
  }>
  affectedSessionIds: string[]
  effectivePolicy: 'future-model-requests'
}
```

至少区分以下错误：

| 错误 | 含义 | 前端行为 |
| --- | --- | --- |
| `PROMPT_REVISION_CONFLICT` | 磁盘版本已变化 | 保留草稿，展示冲突比较 |
| `PROMPT_REQUIRED_EMPTY` | 必需文件将为空 | 定位到对应块，不提交 |
| `PROMPT_TOO_LARGE` | 超过字节限制 | 显示实际与允许字节数 |
| `PROMPT_FILE_NOT_REGISTERED` | 文件或 Session 未登记 | 拒绝，不提供路径纠正入口 |
| `PROMPT_BACKUP_FAILED` | 写入前备份失败 | 不修改正式文件 |
| `PROMPT_WRITE_FAILED` | 写入失败 | 保留草稿，报告恢复状态 |
| `PROMPT_READ_FAILED` | 文件无法读取 | 保留已有界面，不清空草稿 |

这些是人机管理 API，**不新增任何模型工具，因此没有给爱莉暴露的工具 Schema**。

## 10. 权限与安全边界

1. 页面和写接口必须复用 ElyHarn Web 的管理认证，不能公开匿名访问。
2. 写接口仅接受注册表中的 `fileId`，拒绝路径、符号链接逃逸和未登记文件。
3. 备份与审计目录必须在所有模型可读、可写工作区之外。
4. 管理 API 不继承爱莉的模型文件工具身份，也不能被爱莉通过 `bash` 等方式间接调用为提权入口。
5. 页面不返回渠道配置、模型 Key、管理令牌或无关环境变量。
6. 正文按纯文本编辑和展示，不把 Markdown HTML 当作可执行页面内容注入。
7. 普通模型 `write`／`edit` 的现有提示词权限策略不因管理页面上线而放宽。
8. 首版不提供“删除提示词文件”和“强制覆盖冲突”按钮。

## 11. 验收标准

验收优先使用隔离的测试提示词目录和测试 Session，不拿线上人格正文做破坏性试验。

### 11.1 注册与展示

- 页面准确列出首版三个 Session 及第 2.2 节所述有效文件顺序。
- 记忆潜意识页面不会凭空出现 `MEMORY.md`。
- `SOUL.md`、`USER.md`、`MEMORY.md` 的共享影响范围显示正确。
- 动态段和文件块有明确区别，时间消息不出现在固定提示词中。

### 11.2 编辑与预览

- 编辑、撤销、重做、逐块放弃、全部放弃和离开拦截均可用。
- 草稿预览与磁盘预览不会混淆。
- 可选空块被跳过；必需空块被拒绝；连接顺序和 `\n\n` 规则与真实加载器一致。
- token 始终标记为估算。

### 11.3 保存与生效

- 保存前生成维护备份，保存后返回新 `revision`。
- 不清空对话、不重启服务，之后新发起的测试请求使用新正文。
- 已经发出的请求保持原内容，不被追溯修改。
- 保存共享文件后，所有受影响 Session 的下一次读取得到同一新版本。
- 保存成功不会被误报为“模型已经阅读并理解”。

### 11.4 冲突与故障

- 两个页面基于同一版本编辑时，后保存者收到冲突，前者内容不被静默覆盖。
- 模型文件工具或人工在页面外修改文件后，旧页面保存同样能检测冲突。
- 必需为空、超限、备份失败时正式文件不变。
- 模拟多文件写入中途失败时，系统报告真实写入与恢复状态，不假装整批成功。
- 未登记路径、未登记 Session 和匿名写请求全部被拒绝。

## 12. 实施顺序

### 阶段 A：只读骨架

- 建立统一 Session／文件注册表；
- 实现读取、真实固定提示词预览和估算统计；
- 完成三 Session、共享关系和只读动态段展示；
- 不写正式文件。

### 阶段 B：安全编辑与保存

- 完成分块编辑器、脏状态、撤销、差异和离开保护；
- 实现 `revision` 冲突检查、备份、原子写入和审计；
- 用隔离目录验证保存与后续请求生效边界。

### 阶段 C：维护体验

- 查看备份与审计记录；
- 经确认后从历史备份恢复，并再次走冲突校验和新备份；
- 视实际需要增加持久草稿，但仍需与正式生效版本清楚分离。

## 13. 明确决策

- 首版入口是 ElyHarn Web 的独立管理页面，不属于桌宠。
- 首版管理主意识、潜意识中枢、记忆潜意识三个 Session。
- 保存即写入正式文件，不额外引入“应用”状态。
- 新内容用于之后新发起的模型请求，当前已发请求不变。
- 不需要也不允许通过清空对话来让提示词生效。
- 共享文件必须显式显示全部影响范围。
- 自动内容只读，固定文件与运行时动态段分开展示。
- 首版不提供变量插值、强制覆盖、任意路径编辑和模型工具入口。
