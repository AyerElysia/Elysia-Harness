# 爱莉直播舞台与直播姬

当前接入目标为 Spark 上的 `@elysia/dsh-livestream`：它从上游 [dsh-livestream 固定提交 6c2f405b5520bea932808c224ba9ca6d65f41756](https://github.com/luckui/dsh-livestream/tree/6c2f405b5520bea932808c224ba9ca6d65f41756/packages/dsh-livestream) 移植原完整控制台、舞台、三个模板及媒体工作流，配合 Windows 本机 B站直播姬发布。实现说明见 [新包 README](../../plugins/dsh-livestream/README.zh.md)。此前自写的简化原型已移到 Spark 私有工程归档。本页描述接入与验收要求，不代表部署或真实声音验收已经完成。

## 入口与职责

- DSH 已登录界面 → 侧栏「直播」：主人控制台，负责连接直播间、设置、登录、预览、模拟观众及启停爱莉的直播回应。
- Windows 本机 `http://127.0.0.1:3300/source`：直播姬使用的出声舞台入口，依赖到 Spark `127.0.0.1:3300` 的 SSH 本机转发。
- Windows 本机 `http://127.0.0.1:3300/stage`：兼容预览入口，跳转为 `preview=1`，静音且不算出声舞台；控制台内嵌预览同样静音。
- 直播姬：持有场景、混音和平台推流的开播/下播。当前 `publisher=livehime` 时，「开始直播回应」不会启动 OBS 或代替直播姬开播；结束回应也不等于平台下播。

原 OBS 路径仅在明确选择 `publisher=obs` 时使用。直播姬部署不需要先安装或检查 OBS。

## 从旧舞台迁移

运维统一切换 profile 的依赖、bundle 与插件行后，只保留新插件启用，避免两个插件争用 3300 端口或固定会话。不要清理会话、重建人物或导入私聊来完成迁移。

Windows 已添加的 `/source` 地址可以保留，但切换后必须刷新浏览器源一次。旧自写页的事件和音频协议与原版舞台不同，仅等待旧页面自动接回不够。原版控制台的舞台完整地址带 token；无需把该地址或运行设置贴到共享文档。

固定会话继续使用 `elysia-livestream` 与 `homes/web/livestream`，走原生持久化及既有驻留提示词。没有独立人物、观众记忆库、人格蒸馏或自动观众打分。空闲注意窗口允许主体选择回应或略过。

## 接入和验证声音

1. 复用 Windows 现有到 Spark 的 SSH 本机转发，在直播姬场景添加或刷新 `http://127.0.0.1:3300/source` 浏览器源。按模板画布设置尺寸，默认可用 1920×1080。
2. 保持来源启用、允许网页音频，并确认它进入直播姬输出混音。若浏览器源输出到系统设备，同时检查桌面音频的收录与静音设置。
3. 若舞台提示拒播，在浏览器源交互窗口点击启用后续语音。本句失败会如实回报，不自动伪装成功或重播已经交还所有者的旧句。
4. 只需声音时可缩小源或放在其他画面下层，保持页面运行和声音输出。不要选择会卸载网页的隐藏方式，也不要重复添加多个出声舞台。
5. 用播放状态、直播姬音量表及本地录音分别验收。实际公开开播和发送测试弹幕是独立动作；运维验证不自动替用户执行。

Breeze 沿用本机固定音色，无云端语音回退。控制台「已配置」只表示配置和参考文件可读，不证明服务在线。WAV 总时长可由 PCM 长度测得；逐字字幕仍是估算。

舞台 `.ls-viewport` 提供 `data-playback-state`、`data-playback-line-id` 和 `data-last-ended-id`。`playing` 只说明浏览器接受了播放，`data-last-ended-id` 只由实际媒体 `ended` 更新；失败、打断和超时分别回报 `failed`、`cancelled`、`timeout`。预览不发送语音完成回执。

实际 `ended` 证明这一播放器走到音频末尾，不能证明直播姬已混入声音、平台已收到音轨或观众已听到。字幕、出声舞台连接数和媒体下载成功也不能替代这些验证。

## 访问与私有数据

主人 API `/api/dsh-livestream/*` 通过 DSH 鉴权访问。账号登录、Cookie 保存、设置、模拟输入与启停回应都在这个管理面，不在公开舞台端口操作。

独立舞台仅提供带 capability 的页面、模板/角色素材、事件流、媒体读取，以及 `/said`、`/media` 的有限播放回执。它没有登录、Cookie 保存或推流管理入口。token 是私有能力，不写入提交、截图、日志输出或共享链接。

无 token 的 `/source`、`/stage` 兼容跳转只接受直接回环客户端和实际端口的精确回环 Host；带 `Forwarded`、`CF-Connecting-IP` 或 `X-Forwarded-*` 的请求不能领取舞台能力。公开代理上的请求仍需已有有效 capability，不应为适配浏览器源关闭 DSH 鉴权或扩大舞台监听。

`homes/web/dsh-livestream` 中的 `settings.json`、舞台 token、运行状态与媒体缓存属于本机运行数据，目录已被忽略。主体会话历史由原生持久化管理；诊断仅记录时间、状态、序号、音频大小/时长等工程信息，不输出私聊、提示词或凭据。

## 定位与回滚

- 没有舞台连接：先检查本机转发、浏览器源是否仍启用，以及迁移后是否刷新了页面；预览连接不计入出声舞台。
- 有字幕但没有声音：检查舞台的真实失败状态，再看直播姬音量表和混音；不要把字幕进度当作声音成功。
- 完全没有新语音：检查固定直播会话是否恢复、是否启用直播回应，以及本地 Breeze 状态；不要拿私聊作为直播输入测试。
- 舞台显示失败或断线：记录工程状态，检查连接和媒体错误。刷新后等待新的语音，不通过伪造 `ended` 解除所有权。

恢复版本时由运维选择已验证的工程提交，针对性恢复依赖、bundle 与启用行，再统一完成受控重载和浏览器源刷新。保留原生会话与运行数据；旧简化原型只有私有工程归档，不作为可运行回退版本，不能与当前插件同时挂载。恢复工程版本也不等于完成声音混音验收。

## 本地声音的实际验收与恢复

- 先区分“打开直播姬”“启用直播回应”和“向平台推流”。仅开始直播回应会启动本地舞台语音，不会替直播姬公开开播。
- 控制台 Failed to fetch 或舞台断线时，核对本机 3299/3300 的 SSH 转发与 Spark 实际端口 owner；页面残留的旧状态不能证明仍在线。仅在确认没有现存转发 owner 后手动建立一次转发，不增加自动重拉。
- 原生 Tools 的 restrict 只筛全局工具；直播 scope-local 能力由实际注册控制。不得把局部工具名传到全局 allow，否则固定会话恢复会失败；不得靠重建 session 或清理 lock 回避错误。
- Python、主意识与直播都向同一个 Breeze 服务提交一次请求；全局有界 FIFO 与唯一推理 worker 归服务端所有。JS 两端共用 `requestBreeze`，不再通过各自的本地排队或 409 轮询争用推理槽。caller、配置与可选 `requestTimeoutMs` 合成一个截止时间，覆盖排队、执行及完整 PCM；不得重置每次 attempt 的预算，也不得为了赶时限截断正文或播放未完成的 WAV。
- 完整验收要关联同一真实弹幕的 native input、assistant source、WAV 广播 id 和真实 ended。工具成功、字幕、HTTP 200、health=ok 均不能单独证明语音播完。
- 共享服务当前契约为最多 8 个 waiting、1 个 active，排队预算 30 秒、单 job 总预算至多 300 秒。`X-Breeze-Timeout-Ms` 只能缩短上限，`X-Breeze-Client` 仅携带不含用户信息的工程标签。满队列或未就绪返回 503（可带 Retry-After），排队超时返回 504；客户端不盲重投 POST。HTTP 断连取消排队/执行，服务端持有 worker 直到实际清理；200 后失败必须断流，不能把半截 PCM 正常收尾。排障记录安全的 X-Request-ID、HTTP 状态、耗时和音频长度；X-Cancel-Token 是私有取消能力，不输出到日志或共享记录。恢复仍须核对准确服务 owner，不做定时重启。
- 未推流时只能确认本地声音链路；观众侧声音仍需开播后的直播姬混音或平台回放验证。
