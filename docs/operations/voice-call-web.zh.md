# 本机打开实时通话

适用 Spark 的 `@elysia/voice-call` Web 面板。用户已明确同意复用本机现有代理作为本项通话的专用 OpenAI 出口；不得扩展为修改系统代理、全局 Node dispatcher、其他模型路由或公开代理端口。

## 连接形态

- 本机浏览器：`http://127.0.0.1:3299/`，保留宿主原有认证。
- UI 转发：本机 `127.0.0.1:3299` → Spark `127.0.0.1:3299`。
- 专用出口：Spark `127.0.0.1:17878` → 本机已有 MyClashCore `127.0.0.1:7878`。
- 仅 Web profile 的 voice 行设置 `enabled:true` 与 `openaiProxyUrl:http://127.0.0.1:17878`。插件源码默认禁用、未设置代理时走直接连接。
- key 仍在 Spark 受控引用 `OPENAI_REALTIME_API_KEY`，不传到浏览器或代理配置。通过 CONNECT 的 OpenAI HTTPS/WSS 继续验证证书，不跟随重定向到其他域。
- Breeze 仍走 Spark 本机7862，原参考音频不变，不经过该代理。

两个转发都是本轮人工建立的临时 SSH 连接，不是自启动或自动恢复任务。保持本机代理及 SSH 运行；关闭它们后通话会失败并清理，不偷偷切其他模型或声音。

## 以后重新连接

先检查相关本机和远端端口的准确 owner，已有正确转发时不要重复启动、不要杀未知 PID。没有转发时，可在私密终端手动运行现有 SSH 配置（前台、退出即断开，不安装服务）：

```sh
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:3299:127.0.0.1:3299 -R 127.0.0.1:17878:127.0.0.1:7878 dgx-spark
```

现有 MyClashCore 端口若改变，需先核对它的 owner，再显式改这一项转发；不能凭常见端口猜测。不得增加 `GatewayPorts`、监听公网或改用跳过TLS验证。

## 使用面板

1. 在本机 Chrome 打开既有 DSH 页面，进入左侧“实时通话”。
2. 确认隐私说明；本程序不录音、原声不可回放，声音仍会发给 OpenAI 处理，其云端政策由服务约定管理。
3. 用户本人点击“开始通话”并处理浏览器麦克风权限。只有 SSE、WebRTC及后端就绪后才发送声音。
4. 试说一句短话，观察生成字幕与 Breeze 播放；可用静音、停止当前播放和挂断。最多10分钟，不自动重拨。

入口打开、凭据已配置、模型元数据 HTTP200，都不等于实际 WebRTC/插话/播放已验收。只有经过真实短通话才能报告听感和延迟。界面生成字幕也不等于已经听见。

`elysia-voice-call` 是通话插件专用身份，不是可由普通文字会话恢复的 Agent。插件使用公开的原生创建钩子只为该身份检查真实 VoiceAgent 及其插件生命周期归属；其他会话和默认工厂不变。通话结束后专用 Agent 离线是正常现象，不代表 Web 程序关闭。

普通会话的历史 follow 会在冷快照后自动激活默认 Agent，浏览器恢复选中会话或历史流重连可能走到它。专用语音身份现在拒绝这种激活，并由原生工厂回滚临时注册与写锁。请从“实时通话”面板开始新通话，不要用普通文字会话的恢复动作代替拨号；保留的 Session 记录不会因此删除。

## 排查及回收

- Spark 直连 OpenAI 若 TLS reset，不能直接说 key 无效；先区分连接阶段与真实 HTTP401/403/404。
- 代理不可用时只修此项链路，不重启共享 TTS，不修改主意识。
- 关闭时先在面板挂断，等待结束/失败的明确状态，再结束本任务拥有的转发。不要删除语音 Session 或权威记录。
- 凭据更换见 [凭据维护](voice-call-credentials.md)，无需重启。运行验收证据见 [MVP记录](../report/voice-call-mvp-20261112.md)。

## 开始失败时看哪里

- 浏览器只为“开始通话”请求预留 100 秒（涵盖服务器的启动与清理、不是预期等待时间）；服务器启动目标上限 30 秒，Realtime 创建整个流程 25 秒，模型 HTTP、SDP、连接和配置确认单步最多 15 秒；本地操作仍为 10 秒。启动计时在准备完成后清除，不作用于已连接通话。用户主动挂断会立即取消本地捕获和等待，不会等待启动时限耗尽。
- `server_start / TimeoutError` 且无 HTTP 状态表示浏览器没收到回应，不能判定请求没有到服务器或密钥无效。服务器总启动时限触发则返回 `start_timeout`（HTTP 504）。工程记录包含开始、固定阶段及终态最后的服务器与模型建连阶段，不记原始错误或语音。

页面现在保留失败阶段（播放器、麦克风、实时连接准备、连接地址收集、服务器初始化、实时连接确认）。故障详情只显示固定代码、白名单浏览器异常名和有效 HTTP 状态；不显示上游原文、SDP、凭据或设备名称。

- `start_failed_agent_prepare`：后端原生语音 Agent / SOUL 准备失败，不能归因为麦克风权限。
- `start_failed_breeze_config` / `start_failed_credential_resolve`：分别检查语音配置、受控模型凭据引用；不需要把 key 发进聊天。
- `start_failed_provider_create`：区分本服务的 HTTP 状态和额外显示的上游 HTTP 状态。只有真实上游401/403才能支持认证/权限判断；网络失败且没有该状态时不能断言 key 错误。
- 发生任何失败后仍不自动重拨。修复后由用户再次点击开始；此前的字幕、模型元数据200或离线测试均不代表已经打通真实声音链路。
