# 爱莉桌面宠物需求

状态：**需求草案，待讨论与审定；尚未开始实现。**

本文参考 `Pal-AI-Lab/Coopanion`，为爱莉设计一个住在桌面上的长期交互入口。桌宠不是新的 Agent，不另建人格、记忆或主意识 Session；它是 ElyHarn 的一个新渠道和本地身体。

## 2. 产品目标

桌宠需要让使用者感到：爱莉不是偶尔打开的聊天页面，而是在桌面上持续存在、可以回应和互动的同一个主体。

首版核心体验：

1. 爱莉以现有 Live2D 形象出现在桌面工作区。
2. 可以打字叫她，也可以戳、摸头、拖动和隐藏她。
3. 她通过桌面气泡回复，内容与 QQ／KOOK 一样来自同一个主意识。
4. 她能表现倾听、思考、说话、开心、休息等可见状态。
5. 可以播放她真实合成的声音，并让嘴型与声音基本同步。
6. 断线、休息、隐藏和故障都有明确表现，不假装在线。
7. 桌宠操作不会绕过主意识直接执行模型、工具或电脑操作。

## 3. 基本假设

本草案按以下部署形态设计：

- 第一平台是使用者日常使用的 **Windows 10／11** 桌面。
- 桌宠客户端运行在本地电脑，ElyHarn 与模型服务运行在 Spark。
- 本地客户端不保存 DSH Web 管理令牌，不直接访问模型供应商密钥。
- Live2D 原模型保留在受控数据目录，客户端使用经过确认的本地副本。
- macOS、Linux、多显示器和公开安装包不属于首版验收。

## 4. 借鉴与不照搬

### 4.1 值得借鉴

- 透明、无边框、置顶、身体区域之外点击穿透。
- 气泡对话与少量清楚的桌面状态。
- 戳、摸头、拎起、拖动等直接互动。
- 互动事件合并与唤醒策略，避免每次指针划过都调用模型。
- 形象动作词表与模型动作能力对应。
- 语音输入可以打断当前说话。
- 设置与桌宠身体分离，不让设置窗口承担桌宠渲染。
- 形象包在受限环境中运行，不获得主意识或系统权限。

### 4.2 不照搬

- 不运行 Coopanion 的 Cortico Core、Persona、Memory 和 Provider 作为爱莉大脑。
- 不创建 Coo 或第二个爱莉 Session。
- 不复制其模型供应商、记忆文件、扩展市场和 World 管理体系。
- 首版不做屏幕读取、鼠标键盘控制、终端操作。
- 首版不做 OBS、Steam、公开形象市场、自动更新和匿名统计。
- 不直接复制 AGPL 代码；若后续决定复用，先明确源码开放、署名和衍生作品义务。

## 5. 方案选择

| 方案 | 问题或价值 | 结论 |
|---|---|---|
| 原样运行 Coopanion，再把它与爱莉并行启动 | 会出现两套人格、记忆、模型与会话 | 不采用 |
| 把整个 Coopanion 改成 ElyHarn 前端 | 改动面大，仍受 Cortico 生命周期约束 | 不作为首选 |
| 只复用桌宠 World | 可减少窗口与互动工作，但仍依赖 Cortico API 和 AGPL 集成 | 技术验证后再决定 |
| 新建薄 Electron 客户端，借鉴交互，通过专属通道连接 ElyHarn | 主体关系最清楚，可复用现有主意识与渠道接口 | 首选 |
| 使用简单精灵图代替 Live2D | 容易落地，但浪费现有模型，表情和物理连续性较弱 | 仅作渲染故障回退 |

首选结构：

```text
本地 Windows
  Elysia Desktop（Electron）
  ├─ Live2D 身体与物理
  ├─ 气泡、文字输入与互动
  ├─ 音频播放与嘴型
  └─ 专属安全连接
              │
              ▼
Spark
  @elysia/desktop-channel（Cordis 插件）
  ├─ inboundPending.receive
  ├─ outboundText.register('desktop')
  ├─ outboundVoice.register('desktop')
  └─ 桌面状态与动作事件
              │
              ▼
  elysia-conscious-mind（唯一主意识）
```

建议未来代码位置，当前不创建：

```text
Elysia-Harness/apps/desktop-pet        本地 Electron 客户端
Elysia-Harness/plugins/desktop-channel ElyHarn 渠道插件
```

## 6. 角色与权限边界

### 6.1 本地客户端

负责：

- 渲染身体、气泡、控件与状态；
- 采集文字、明确的触摸和拖动互动；
- 在使用者主动操作后采集麦克风；
- 播放文字对应的语音和管理本地动画；
- 显示连接、隐藏、静音和休息状态。

不负责：

- 直接请求聊天模型；
- 持有主意识系统提示词或修改人格；
- 自行生成回复；
- 读取任意文件、屏幕或其他应用；
- 执行潜意识派工或修改记忆；
- 在后台持续截屏或调用模型。

### 6.2 desktop-channel 插件

负责：

- 验证客户端身份与会话归属；
- 把桌面输入转换为现有 `InboundEvent`；
- 注册 `desktop` 文字与语音 sender；
- 转发动作、状态和播放控制；
- 管理连接、心跳、回执和有界重连；
- 记录真实投递错误。

不负责：

- 创建或恢复任何 Agent；
- 自行回复使用者；
- 修改 `send_text` 的四类内在字段与换行拆分契约；
- 把桌面输入直接交给潜意识专业 Session；
- 暴露 DSH 通用管理 API。

### 6.3 主意识与潜意识

- 主意识决定是否回复、回复什么、使用文字还是语音。
- 主意识可决定是否执行已开放的身体动作。
- 潜意识继续通过主意识真实事件接收桌面输入与输出。
- 潜意识不直接控制身体，不获得桌面渠道发送权。
- 主动系统未来可以形成机会，但最终表达仍由主意识决定。

## 7. 桌面渠道身份

### 7.1 入站

使用现有 `InboundEvent`：

```ts
{
  channel: 'desktop'
  conversation: string
  messageId: string
  senderId: string
  senderName: string
  content: InboundContentPart[]
}
```

建议：

- `conversation` 使用稳定的 `desktop:local:<installation-id>`；
- `installation-id` 是本地随机生成、长期保存的非身份敏感 ID；
- `messageId` 由客户端为每次输入生成 UUID；
- `senderId` 使用本地显式配置，不与 QQ／KOOK 账号自动归并；
- 文字、语音转写和互动使用明确标签，不把触摸伪装成用户说出的自然语言。

示例：

```text
[typed] 你好，爱莉
[voice] 我现在有点累
[touch] 使用者戳了爱莉 1 下
[touch] 使用者摸了摸爱莉的头
[drag] 使用者把爱莉移动到了桌面右侧
```

### 7.2 出站文字

继续调用现有：

```ts
send_text({
  channel: 'desktop',
  conversation: 'desktop:local:<installation-id>',
  thought,
  mood,
  decision,
  expected_response,
  content
})
```

桌面渠道接收已经按换行拆好的每一段，并按顺序显示为气泡。不得把 `thought / mood / decision / expected_response` 显示在气泡中。

### 7.3 出站语音

普通语音继续通过 `outboundVoice` 接收 `audio/wav`：

- 客户端确认完整音频可用后再返回成功回执；
- 播放期间驱动嘴型，并同步对应气泡；
- 新语音是否打断旧语音由主意识本轮输出顺序和本地明确的打断规则决定；
- 连接断开时返回失败，不在客户端静默伪造播放成功。

实时通话不塞进 `send_voice` 的完整 WAV 契约，复用独立通话控制与 PCM 流。

## 8. 连接协议需求

使用专属、经过身份验证的 WebSocket 通道；远程部署必须经 TLS 或既有安全隧道。不得把 ElyHarn Web 管理令牌作为桌宠长期凭证。

最小消息类型：

| 类型 | 方向 | 用途 |
|---|---|---|
| `hello / welcome` | 双向 | 协议版本、安装 ID、能力与连接代次 |
| `input` | 客户端 → Spark | 文字、转写或互动事件 |
| `output.text` | Spark → 客户端 | 一段气泡文字 |
| `output.voice` | Spark → 客户端 | 一段语音及对应文字／消息身份 |
| `action` | Spark → 客户端 | 已授权的身体动作或移动 |
| `status` | Spark → 客户端 | 思考、忙碌、休息等服务状态 |
| `ack` | 客户端 → Spark | 文字、语音或动作的接收／执行回执 |
| `interrupt` | 双向 | 停止当前语音、动作或实时通话 |
| `ping / pong` | 双向 | 连接健康检查 |
| `error` | 双向 | 可定位的协议或执行错误 |

每条输出具有稳定 `messageId` 和连接内顺序。客户端回执必须带同一 `messageId`，不能让渠道仅凭 WebSocket 写入成功就宣称桌面已显示或播放。

重连要求：

- 使用有界退避，不密集重连；
- 重连创建新连接代次，旧连接消息不得操作新界面；
- 未确认的出站不得盲目自动重发；
- 客户端明确显示离线，离线输入留在本地并允许取消；
- ElyHarn 重启后不得重复提交已经确认的桌面入站事件。

## 9. 桌面窗口与身体

首版必须具备：

- 透明、无边框窗口；
- 默认位于当前工作区底部，不遮挡任务栏；
- 身体、气泡和按钮接收点击，其余区域点击穿透；
- 可拖动位置、调整大小、隐藏和恢复；
- 置顶可开关；
- 全局鼠标穿透模式，并能清楚退出；
- 断开 ElyHarn 时身体仍可显示，但有离线状态；
- 减少动态效果设置开启时，降低呼吸以外的大幅运动。

首版不做甩出物理、多显示器迁移、眼球持续追踪和 OBS。

### 9.1 Live2D 技术验证

实现前先做独立技术样例，验证：

1. 当前 `.moc3` 与所选 Cubism Web 运行时兼容。
2. 三张大型贴图的加载时间、显存与内存可接受。
3. 透明背景、物理、眨眼、呼吸、视线和嘴型正常。
4. 自定义参数的真实范围与效果已经测量，不凭参数名猜动作。
5. 运行时和模型授权允许预期使用方式。
6. 原模型不被修改；优化贴图或配置时使用单独的运行副本。

技术样例通过前，不承诺所有现有参数都能成为桌宠动作。

## 10. 气泡与交互

### 10.1 气泡

- 支持爱莉气泡、使用者输入气泡、文字输入框和系统状态。
- 长文本有最大宽度、换行和滚动／展开策略，不能无限覆盖屏幕。
- 多段 `send_text` 按顺序显示，不重叠抢占。
- 点击当前气泡可跳过逐字效果，不删除主意识历史。
- 鼠标进入气泡时暂停自动消失。
- 语音播放与对应气泡保持关联。
- 隐私字段、工具参数、文件路径和潜意识报告不进入桌面气泡。

### 10.2 文字输入

- 点击桌宠或悬停按钮打开输入框。
- Enter 发送，Shift+Enter 换行。
- 首版不要求全局打字快捷键；如加入，必须可配置并可关闭。
- 未发送内容在断线重连后保留。
- 发送后进入现有主意识 pending，而不是本地直接回答。

### 10.3 触摸与拖动

首版支持：

| 互动 | 桌面表现 | 是否默认唤醒主意识 |
|---|---|---|
| 单击身体 | 戳一下、短表情 | 可配置，默认戳唤醒 |
| 头部来回移动 | 摸头、短暂开心 | 默认合并后随下一批，不单独频繁唤醒 |
| 按住拖动 | 拎起并移动 | 不唤醒 |
| 拖动结束 | 落到新位置 | 不唤醒 |
| 双击 | 打开文字输入 | 不作为聊天内容 |

互动事件使用 2～3 秒合并窗口，同类连续互动聚合成次数。拖动与点击必须区分，拖动结束不能额外触发戳。

## 11. 状态与动作

### 11.1 本地状态

```text
offline / idle / listening / thinking / speaking / resting / hidden / error
```

- `offline`：没有 ElyHarn 连接。
- `idle`：在线且没有活动输入输出。
- `listening`：使用者明确开启麦克风。
- `thinking`：桌面输入已进入主意识，等待本轮结果。
- `speaking`：正在播放语音或展示对应回复。
- `resting`：使用者明确暂停互动。
- `hidden`：不绘制身体，但不等于退出或删除会话。
- `error`：展示可以理解的故障，不假装仍在思考。

状态只来自真实连接、输入、主意识轮次和播放事件，不使用定时动画假装她在工作。

### 11.2 模型主动作

首版可以先由文字、语音和本地互动驱动固定动作。若验证需要主意识主动选择动作，再新增 `desktop_act`：

```ts
interface DesktopActArgs {
  conversation: string
  actions: string[]
}
```

- `conversation` 必填，必须是当前桌面会话；
- `actions` 为 1～4 个当前形象已登记动作 ID；
- 工具只提交动作请求，不代表已经执行；
- 客户端回执包含实际执行和被拒绝的动作；
- 不接受文件路径、代码、URL、任意参数写入或自定义脚本。

返回：

```ts
{
  conversation: string
  accepted: string[]
  rejected: string[]
  messageId?: string
  error?: string
}
```

动作词表必须来自实际验证过的爱莉模型配置，例如 `greet / love / happy / shy / think / sleep` 只能在映射确认后开放。

### 11.3 主动移动

首版只提供使用者拖动和可关闭的少量自动散步。若以后让主意识控制位置，再增加：

```ts
interface DesktopMoveArgs {
  conversation: string
  to: number | 'left' | 'center' | 'right'
  run?: boolean
}
```

`to` 为数值时限制在 0～1。移动最多持续 30 秒，可被拖动、隐藏、休息和打断终止。该工具不属于首版最小交付。

## 12. 语音与实时通话

### 12.1 普通语音消息

先于实时通话实现：

- 主意识通过现有 `send_voice` 发出完整语音；
- 桌面端播放真实 WAV，不生成替代音色；
- 用实际音频振幅或可用音量数据驱动 `ParamMouthOpenY`；
- 播放结束、跳过、隐藏或断开时嘴型归零；
- 默认不自动播放未预期语音，提供静音与音量控制；
- 不在公开直播中输出受限制模型形象。

### 12.2 语音输入

建议采用按住说话，而不是默认持续收音：

- 只有使用者明确按住或开启时才取得麦克风；
- 松开结束本句；
- 支持取消，取消后不投递；
- 识别引擎与部署位置经技术验证后选择；
- 转写失败保留可理解的错误，不发送空消息；
- 不把环境音默认为使用者发言。

### 12.3 实时通话

实时通话是后续独立阶段：

- 使用者显式开始和结束；
- 复用现有 `elysia-voice-call`、Realtime 输入、Breeze PCM 流和插话取消；
- 不与普通主意识文字轮次混成同一个工具回执；
- 每通只保留一个在途合成，短句输出；
- 开口打断时取消旧代音频并清空本地队列；
- 桌宠只提供身体、麦克风、播放与状态界面，不另写一套通话引擎；
- 真实端到端通话必须另外验收，不能用 PCM 离线测试替代。

## 13. 设置与本地数据

首版设置只需要：

- 服务地址与桌宠专属凭证的安全设置入口；
- 使用者称呼；
- 窗口置顶、大小、位置、隐藏和鼠标穿透；
- 自动散步与触摸回应模式；
- 音量、静音和语音播放；
- 麦克风与说话方式；
- 减少动态效果；
- 连接状态、最近错误与重新连接。

本地保存窗口偏好、安装 ID 和必要凭证。凭证使用系统安全存储或受保护配置，不写入日志，不进入模型上下文。

不复制 Coopanion 的 Persona、Memory、模型价格和用量页面；这些仍由 ElyHarn 或未来专门管理界面负责。

## 14. 休息、隐藏与故障

- **隐藏**：只隐藏本地身体，不停止 ElyHarn，不暂停其他渠道。
- **休息**：桌面渠道不再因普通触摸唤醒主意识；文字是否仍发送由明确设置决定。
- **离线**：不伪造回复，不继续显示“思考”。
- **ElyHarn 重启**：客户端有界重连，主意识 Session 保持不变。
- **渲染失败**：显示可读错误并允许使用静态回退形象；不回退成 Coo。
- **音频失败**：文字仍可显示，语音回执写明失败。
- **模型超时**：结束本地思考状态，保留输入与重试入口，不重复自动发送。

## 15. 安全、隐私与许可

1. 桌面端不暴露 DSH 管理 API、模型 Key、Breeze 配置或其他渠道凭证。
2. 首版无截屏、鼠标键盘控制、Shell、任意文件读写和扩展代码安装。
3. 麦克风只在明确语音交互时启用，并有持续可见状态。
4. 日志不记录完整聊天、语音内容、凭证或本机敏感路径。
5. 模型原始资源不进入公开 Git 仓库，不随公开应用分发。
6. 当前模型禁止直播与售卖，首版不提供 OBS 或商业分发。
7. 若复制 Coopanion 代码，单独审查 AGPL-3.0-or-later 义务、第三方资源许可和 Cubism SDK 许可。
8. 桌面互动和输出仍进入现有 Observation 接收线，保持来源与因果关系可追溯。

## 17. 分阶段实施

### 阶段 0：技术样例

- Live2D 在透明 Electron 窗口中正常显示。
- 验证物理、眨眼、呼吸、嘴型、自定义参数和性能。
- 确定是否完全自研薄客户端，或复用 Coopanion 的哪些窗口思路。
- 完成许可与模型使用边界核对。

### 阶段 1：桌面文字闭环

- 桌面窗口、身体、气泡、输入、拖动、隐藏。
- `desktop-channel` 接入 `inboundPending / outboundText`。
- 主意识用现有 `send_text` 回复桌面。
- 触摸事件合并与唤醒策略。
- 离线、重连和真实回执。
- 桌面活动进入潜意识 Observation。

### 阶段 2：声音与动作

- `outboundVoice` 和 WAV 播放。
- 语音关联气泡与振幅嘴型。
- 实际验证后的动作词表。
- 必要时加入 `desktop_act`；主动移动另行审定。

### 阶段 3：语音输入与实时通话

- 按住说话、ASR、取消与错误处理。
- 复用实时通话 Session 和 PCM 插话链路。
- 完成真实端到端通话验收。

### 阶段 4：后续体验

- 多显示器、更多互动、全局快捷键、精细装扮。
- 只有获得相应授权后才考虑 OBS 或公开形象分发。
- 电脑操作若未来确有需要，作为独立高风险项目设计，不附带在桌宠里自动获得。

## 18. 首版验收

首版完成必须同时证明：

1. 本地 Windows 出现正确的爱莉 Live2D 身体，而非 Coo 或静态占位图。
2. 透明、置顶、点击穿透、拖动、隐藏和恢复正常。
3. 桌面文字进入现有主意识 Session，不产生新 Agent。
4. 主意识通过 `send_text(channel='desktop')` 回复，气泡按拆分段顺序显示。
5. 多段输出有真实客户端回执，断开时不伪报成功。
6. 戳、摸头和拖动符合事件合并与唤醒规则，不形成模型调用风暴。
7. 主意识这些输入、工具调用和输出形成对应 Observation。
8. ElyHarn 重启或短暂断线后，桌面可以恢复且不重复提交已确认输入。
9. 离线、休息、思考和错误状态真实可见。
10. 桌面端没有模型 Key、DSH 管理令牌、电脑操作和任意代码执行。
11. 自动化测试覆盖协议、回执、去重、重连、动作校验和渠道注册。
12. 普通语音与实时通话若尚未进入对应阶段，明确标为未交付，不用文字闭环冒充。

## 19. 本轮需要讨论的决定

1. 首版是否确认以 Windows 本地客户端＋Spark ElyHarn 为部署形态。
2. 是否采用现有 Live2D 模型作为唯一首版形象，不另做精灵图主体。
3. 是否同意首版只做文字、基础互动与普通语音，实时通话随后接入。
4. 是否同意不做电脑操作、OBS、扩展市场和公开模型分发。
5. 是否优先自研薄客户端，仅借鉴 Coopanion；还是在技术样例后复用其桌宠 World 的窗口层。
6. 默认哪些触摸应该唤醒主意识，哪些只作本地回应。
7. 主意识是否需要 `desktop_act`，以及首批真正可用的动作词表。

这些决定不影响核心边界：**桌宠是爱莉的身体和新渠道，不是另一个大脑。**
