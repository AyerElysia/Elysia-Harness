# ElyH 目标架构：会话能力与权限

> 目标设计，不描述现状。一个主体、两类意识、两种 worker，按「能读什么、能写什么、能执行什么、不能做什么」定义。
>
> 配图：
> - [elyh-usecase.png](elyh-usecase.png)：**能力视图**（每个用例读什么、写什么），源 `elyh-usecase.html`；
> - [elyh-dataflow.png](elyh-dataflow.png)：**数据流视图**（观察 → 批次 → 决策 → 派工/提议 → 回流），源 `elyh-dataflow.html`。

## 0. 六个用例、三个框

| 框 | 用例 | 一句话 |
|---|---|---|
| **主意识** | 聊天 | 对外表达的主场，所有渠道消息的落点 |
| | 通话 | 实时语音形态 |
| | 直播 | 公开表达形态 |
| **潜意识** | 中枢 Router | 看全量表界，决定忽略 / 延期 / 派工 / 提议；心跳是它的第二种触发 |
| **Worker** | 通用 worker | 干活，每次任务新建 |
| | 记忆 worker | 整理记忆，每次任务新建 + 注入记忆 skill |

## 1. 五条硬约束

1. **外发唯一**：只有主意识（聊天/通话/直播）能对外表达。中枢与两种 worker 一律不能直接对平台说话。
2. **记忆写唯一**：只有记忆 worker 写长期记忆。主意识只读；通用 worker 不读也不写。
3. **观察唯一**：只有中枢 Router 看全量表界流；worker 只看被投递的材料。
4. **派工单向**：worker 不能反向给主意识派活；潜意识对主意识只能是**提议**，主意识决定是否行动。
5. **结果回派工方**：主意识派的 worker，结果回主意识；Router 派的 worker，结果回 Router。Router 再决定要不要让主意识知道——走「提议」，不直接塞给她。

## 2. 中枢链路的四个环节

```text
外界输入 / 主意识输出 / 工具与平台结果
        ↓ 三路汇流
表界观察 SurfaceObservation   全量采集 · 去重 · 持久化
        ↓ 有界批次与游标
中枢 Router                   忽略 · 延期 · 派工 · 提议
        ├─ 派工：Task + Mandate → Assignment → worker → TaskReport
        └─ 提议：ConsciousProposal → 主动系统 → 主意识决定是否行动
主意识输出 ──处理结果回流──→ 表界观察
```

| 环节 | 职责 | 关键约束 |
|---|---|---|
| 表界观察 | 三路来源全量落地，去重、持久化 | 只收主意识**实际接纳**的事实，不是平台网关审计日志 |
| 有界批次与游标 | 把观察切成分批单位投递，漏收可补读 | 批次是不可变投影，超限标 `complete: false` 并给续读地址 |
| Router | 四个决定：忽略 / 延期 / 派工 / 提议 | 不产出正文给用户，产物只有任务、提议、决定记录 |
| 处理结果回流 | 主意识输出重新进入观察 | 闭环靠这条线成立，否则 Router 永远只看得到输入 |

## 4. 主意识 · 聊天

**读**：入站批次（渠道/会话/发送者/消息 id/时间）、图片与文件附件、长期记忆、工作区文件、网络、潜意识提议。
**写**：文字（分段、可停止）、图片、文件、语音（固定音色）。
**执行**：`pass` 明确沉默；派工；接收提议并决定是否执行。
**不做**：直接操纵 live2d、订阅平台原始流、写长期记忆。

## 5. 主意识 · 通话

**读**：实时语音转写、最近聊天上下文、长期记忆、工作区文件、网络搜索。
**写**：实时语音（可打断）、挂断后补一条文字留言。
**执行**：结束通话、异步派工。
**不做**：终端/长任务、直播操作、通话中写记忆。

**工具面（必须少而快）**：`read_memory`（≤300ms，单轮 1 次）、`read_recent_messages`（≤200ms）、`read`/`web_search`（≤800ms）、`dispatch_worker`（立即返回收据）、`send_text`（仅挂断后）、`end_call`。

## 6. 主意识 · 直播

**读**：直播事件、弹幕、私信、观众资料、房间数据、视频库、长期记忆、工作区文件、网络搜索。
**写**：`live_say` 口播（字幕/口型/TTS 对齐）、发弹幕、点赞/关注/投币/发动态（白名单）。
**执行**：live2d 表情/动作/口型、播放视频、切歌、下播。
**不做**：私自私信、改标题、删评论（默认关闭）。

## 7. 潜意识 · 中枢 Router（含心跳）

**触发**：新观察批次 / 心跳唤醒 / 休息状态切换。心跳不再是第二个会话，而是同一个长期会话的第二种触发——同一个会话天然知道自己做过什么，不需要再把「完整上下文」搬运一遍。

**读**：全量表界观察（外界输入 / 主意识输出 / 工具与平台结果）、自己的决定与任务历史、主意识当前状态（是否在直播/通话）、awake / resting。

**决策**：

| 决定 | 含义 |
|---|---|
| `ignore` | 看过了，什么都不做；观察仍保留可追溯 |
| `defer` | 现在不做，到期形成续批 |
| `dispatch` | 生成 Task + Mandate，派给 worker |
| `propose` | 生成 ConsciousProposal：提议开播 / 提议通话 / 提议主动表达 |

**不做**：对外表达、写记忆、亲自干活、读取未授权来源。
**不变式**：Router 不产出正文给用户；产物只有任务、提议和决定记录。

## 8. Worker · 通用

**读**：派工材料、工作区文件、网络/MCP/技能。**不读长期记忆**。
**写**：结果回派工方、工作区文件/代码产物、终端命令与脚本。
**执行**：全部 agent 工具（终端、文件、搜索、web、skill、MCP、代码）。
**不做**：渠道外发、改主体提示词、再派 worker（深度上限 1）、读全量表界流。
**生命周期**：一任务一派工，结束回收；预算 = token / 时间 / 工具调用数。

## 9. Worker · 记忆

**读**：派工材料、**记忆 skill（注入）**、长期记忆（读，用于查重与合并）、工作区文件。
**写**：记忆写入（日记 / 记忆库 / 索引）、`TaskReport` → 派工方。
**派工方**：主意识或 Router，两侧都可以派。
**不做**：渠道外发、改主体提示词、写提示词正文、再派 worker。
**生命周期**：和通用 worker 一样每次任务新建；**它是唯一能写长期记忆的角色**。

## 10. 派工协议（建议字段）

| 字段 | 含义 |
|---|---|
| `task` / `goal` | 要做什么，可验收的一句话 |
| `mandate` | 允许读的来源、允许用的工具、允许写的位置、权限版本 |
| `skill` | worker 类型标识：通用 / 记忆（决定注入哪套 skill） |
| `budget` | token / 墙钟 / 工具调用数 |
| `report` | 回传格式：状态 + 产物指针 + 依据 |
| `deadline` | 到期未完成即 `blocked` |

## 11. 仍需拍板

1. **心跳频率**：建议默认 30 分钟，空闲时退避到 2 小时。
2. **无输入心跳**要不要真的调用模型？建议要——「主动」就来自这一下；但可以设成本上限。
3. **提议去重**：同一对话 24 小时内是否禁止重复提议同一件事？
4. **记忆 worker 的合并策略**：新增即追加，还是定期合并重写？
5. **表界观察的保留期与容量上限**：现在只按批次/字节限制，没有时间维度的清理策略。
