# ElyH 目标架构：会话能力与权限

> 目标设计，不描述现状。一个主体、两类意识、三种 worker，按「能读什么、能写什么、能执行什么、不能做什么」定义。
>
> 配图：
> - [elyh-usecase.png](elyh-usecase.png)：**能力视图**（每个用例读什么、写什么），源 `elyh-usecase.html`；
> - [elyh-dataflow.png](elyh-dataflow.png)：**数据流视图**（观察 → 批次 → 决策 → 派工/触发 → 回流），源 `elyh-dataflow.html`。

## 0. 七个用例、三个框

| 框 | 用例 | 一句话 |
|---|---|---|
| **主意识** | 聊天 | 对外表达的主场，所有渠道消息的落点 |
| | 通话 | 实时语音形态 |
| | 直播 | 公开表达形态 |
| **潜意识** | 中枢 Router | 看全量表界，唯一的派工入口；心跳是它的第二种触发 |
| **Worker** | 通用 worker | 干活，每次任务由 Router 派 |
| | 事件 worker | 由 Router 创建的触发事件自动拉起，Router 不再逐次审核 |
| | 记忆 worker | 整理记忆，每次任务新建 + 注入记忆 skill |

## 1. 五条硬约束

1. **外发唯一**：只有主意识（聊天/通话/直播）能对外表达。中枢与三种 worker 一律不能直接对平台说话。
2. **派工唯一**：只有中枢 Router 能派工。主意识不直接派工——它想要什么，通过表界观察让 Router 知道，或用通信工具直接告诉 Router。
3. **记忆写唯一**：只有记忆 worker 写长期记忆。主意识只读；通用与事件 worker 不读也不写。
4. **观察唯一**：只有中枢 Router 看全量表界流；worker 只看被投递的材料。
5. **结果回派工方**：所有 worker 的结果一律回 Router；Router 决定要不要让主意识知道——走「提议」，不直接塞给她。

## 2. 通信工具（所有 session 可用）

`send_message(to_session, content)`：向任意其他 session 发一条消息。

- **谁都能用**：主意识三面、中枢、三种 worker 全部可用；
- **只到会话之间**：消息进入对方 inbox，不触达任何外部平台，所以不违反「外发唯一」；
- **worker 的汇报不走它**：worker 的结果仍走 TaskReport 结构化回传，通信工具用于协调与补充说明；
- **接收方决定怎么处理**：收到消息不等于必须回应，`pass` 依然有效。

## 3. 中枢链路的四个环节

```text
外界输入 / 主意识输出 / 工具与平台结果
        ↓ 三路汇流
表界观察 SurfaceObservation   全量采集 · 去重 · 持久化
        ↓ 有界批次与游标
中枢 Router                   忽略 · 延期 · 派工 · 提议 · 建触发器
        ├─ 派工：Task + Mandate → Assignment → worker → TaskReport
        ├─ 触发器：发现重复工作 → 创建事件 → 事件 worker 自动执行（不再审核）
        └─ 提议：ConsciousProposal → 主动系统 → 主意识决定是否行动
主意识输出 ──处理结果回流──→ 表界观察
```

| 环节 | 职责 | 关键约束 |
|---|---|---|
| 表界观察 | 三路来源全量落地，去重、持久化 | 只收主意识**实际接纳**的事实 |
| 有界批次与游标 | 投递单位，漏收可补读 | 批次不可变，超限给续读地址 |
| Router | 忽略 / 延期 / 派工 / 提议 / 建触发器 | 唯一派工入口；不产出正文给用户 |
| 处理结果回流 | 主意识输出重新进入观察 | 闭环靠这条线成立 |

## 5. 主意识 · 聊天

**读**：入站批次（渠道/会话/发送者/消息 id/时间）、图片与文件附件、长期记忆、工作区文件、网络、其他 session 的消息、Ayla 内容与关系（他人主页 / 动态流 / 消息列表）。
**写**：文字（分段、可停止）、图片、文件、语音（固定音色）、给任意 session 发消息、**Ayla 操作（任意，见 5.1）**。
**执行**：`pass` 明确沉默；接收提议并决定是否执行；想要 worker 干活时，用通信工具告诉 Router。
**不做**：直接派工、直接操纵 live2d、订阅平台原始流、写长期记忆。

### 5.1 主意识 · Ayla 操作工具

**定位**：主意识对 Ayla 的**主动操作面**。「Ayla 通道」是被动管道——收消息、回消息；这套工具负责她**主动去做事**：发帖、评论、关注、改资料、发起互动，都算操作。

**覆盖面**（按 Ayla 后端能力枚举，原则是「任何操作」）：

| 类别 | 操作 |
|---|---|
| 内容 | 发动态 / 帖子、评论、回复、点赞、收藏、转发、删除自己的内容 |
| 关系 | 关注 / 取关、加好友 / 删好友、拉黑、举报 |
| 消息 | 主动发起私信、撤回、已读 |
| 资料 | 昵称、签名、头像、状态、可见性设置 |
| 互动 | 发起 / 接受通话、发起 / 结束直播、进直播间、送礼 |
| 读取 | 他人主页、好友列表、动态流、消息列表、通知 |

**边界**：

- 只作用于 Ayla，不触达其他平台；
- 走 Ayla 后端公开 API，与「Ayla 通道」共用同一套凭据与限流；
- 按需求默认全开，但保留逐项开关用于紧急关闭；
- 写操作产生的内容同样会以「工具与平台结果」进入表界观察，被 Router 看到。

## 6. 主意识 · 通话

**读**：实时语音转写、最近聊天上下文、长期记忆、工作区文件、网络搜索。
**写**：实时语音（可打断）、挂断后补一条文字留言、给任意 session 发消息。
**执行**：结束通话。
**不做**：派工、终端/长任务、直播操作、通话中写记忆。

**工具面（必须少而快）**：`read_memory`（≤300ms，单轮 1 次）、`read_recent_messages`（≤200ms）、`read`/`web_search`（≤800ms）、`send_message`（异步）、`send_text`（仅挂断后）、`end_call`。

## 7. 主意识 · 直播

**读**：直播事件、弹幕、私信、观众资料、房间数据、视频库、长期记忆、工作区文件、网络搜索。
**写**：`live_say` 口播（字幕/口型/TTS 对齐）、发弹幕、点赞/关注/投币/发动态（白名单）、给任意 session 发消息。
**执行**：live2d 表情/动作/口型、播放视频、切歌、下播。
**不做**：派工、私自私信、改标题、删评论（默认关闭）。

## 8. 潜意识 · 中枢 Router（含心跳 · 唯一派工入口）

**触发**：新观察批次 / 心跳唤醒 / 休息状态切换。
**读**：全量表界观察、自己的决定与任务历史、主意识当前状态、awake / resting。
**决策**：

| 决定 | 含义 |
|---|---|
| `ignore` | 看过了，什么都不做 |
| `defer` | 现在不做，到期形成续批 |
| `dispatch` | 生成 Task + Mandate，派给 worker |
| `propose` | 生成 ConsciousProposal：提议开播 / 提议通话 / 提议主动表达 |
| `arm_trigger` | 发现经常重复的工作 → 创建触发事件，交给事件 worker 自动执行 |

**触发器规则**：Router 只在创建时定义触发条件与产出要求，之后不再逐次审核——worker 跑完向 Router 汇报即可。要停掉一个触发器，Router 显式撤销。
**不做**：对外表达、写记忆、亲自干活（简单工作可以直接完成）、读取未授权来源。
**不变式**：Router 不产出正文给用户；产物只有任务、提议、决定记录和触发器。

## 9. Worker · 通用

**读**：派工材料、工作区文件、网络/MCP/技能。**不读长期记忆**。
**写**：结果回 Router、工作区文件/代码产物、终端命令与脚本、给任意 session 发消息。
**执行**：全部 agent 工具（终端、文件、搜索、web、skill、MCP、代码）。
**不做**：渠道外发、改主体提示词、再派 worker、读全量表界流。
**生命周期**：一任务一派工，结束回收；预算 = token / 时间 / 工具调用数。

## 10. Worker · 事件

**来源**：Router 创建的触发事件。事件定义触发条件与产出要求；事件触发时自动创建本 worker，**Router 不再逐次审核**。
**读**：触发事件配置、工作区文件、网络/MCP/技能。
**写**：结果回 Router（每次运行都汇报）、工作区文件/代码产物、给任意 session 发消息。
**不做**：渠道外发、改主体提示词、改自己的触发条件、再派 worker。
**生命周期**：每次触发新建，跑完汇报即回收。要停掉由 Router 显式撤销触发器。

## 11. Worker · 记忆

**读**：派工材料、**记忆 skill（注入）**、长期记忆（读，用于查重与合并）、工作区文件。
**写**：记忆写入（日记 / 记忆库 / 索引）、`TaskReport` → Router、给任意 session 发消息。
**派工方**：Router。主意识想要整理记忆，用通信工具告诉 Router。
**不做**：渠道外发、改主体提示词、写提示词正文、再派 worker。
**生命周期**：每次任务新建；**它是唯一能写长期记忆的角色**。

## 12. 派工协议（建议字段）

| 字段 | 含义 |
|---|---|
| `task` / `goal` | 要做什么，可验收的一句话 |
| `mandate` | 允许读的来源、允许用的工具、允许写的位置、权限版本 |
| `skill` | worker 类型标识：通用 / 事件 / 记忆 |
| `trigger` | 仅事件 worker：触发条件与产出要求 |
| `budget` | token / 墙钟 / 工具调用数 |
| `report` | 回传格式：状态 + 产物指针 + 依据 |
| `deadline` | 到期未完成即 `blocked` |

## 13. 仍需拍板

1. **心跳频率**：建议默认 30 分钟，空闲时退避到 2 小时。
2. **无输入心跳**要不要真的调用模型？建议要——「主动」就来自这一下。
3. **触发器的粒度**：一个触发器一个事件 worker，还是允许 Router 合并同类触发？
4. **事件 worker 的预算**：自动跑的任务没有人在旁边盯着，预算要不要更紧？
5. **通信工具的消息保留**：worker 发给 Router 的消息要不要落持久存储，还是仅 inbox？
6. **表界观察的保留期与容量上限**。
