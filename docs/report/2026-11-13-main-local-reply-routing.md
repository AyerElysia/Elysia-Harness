# 主意识 DSH 本地回复路由修复

2026-11-13，北京时间。原生 DSH 用户输入触发的第 1225、1226 轮均调用 `send_text` 走 KOOK。每次两段，工具结果有平台消息 ID。报告仅记工程元数据。

旧工具说明没有明确 DSH 正文的显示和播报语义。执行路径接受模型提供的已登记渠道及会话，未读取本轮实际入站来源，因此旧 KOOK 会话可被错误用为收件人。

主意识按当前原生轮次的实际用户输入执行路由保护。DSH 打字和通话转写直接使用当前会话的 assistant 正文。渠道插件创建的批次保留 DSH 可见用户消息类型，并附可信平台来源。普通本地轮次在发送工具执行前拦截外发。当前用户明确要求外发时，可通过现有 DSH 确认卡确认具体渠道、收件会话和内容，批准只对同一执行有效。该机制没有修改用户权限预设。已完成历史与主会话 ID 保留。

109 项主意识插件测试通过。原生 AgentLoop 集成使用模拟渠道验证同一调用在平台入站可送、本地入站被拒；原生确认服务另覆盖伪造答复、取消、卸载和一次性执行。定向 TypeScript 检查通过，全项目原有两项计划插件声明产物缺失。

正式 Spark 在空闲时更新五个运行文件并按原入口启动。主意识原会话恢复，3299、3300 和 18793 监听正常。验收使用模拟渠道。
