# 直播姬独立声音与字幕源验收

2026-11-13，北京时间。工程变更位于 `plugins/dsh-livestream`。

## 直播姬接入

- 声音源 `http://127.0.0.1:3300/audio` 建议设为 320×120。正常播放时页面透明，接收舞台排播的爱莉与嘉宾语音。
- 字幕源 `http://127.0.0.1:3300/subtitles` 建议设为 1280×240。透明背景上仅显示当前语音字幕，长句分页。
- 两个地址各自添加为浏览器源，来源的画布位置可分别调整。声音源保持启用，并检查直播姬的实际输出音轨。原组合舞台 `/source` 可单独使用。
- 同时连接时，专用声音源优先接收下一句。每句只分配一个播放器。字幕在其真实起播后显示，在播放终态或连接断开时清空。字幕源只读，不接收音频载荷。

## 验证

- 直播插件 41 个测试文件，314 项通过，6 项按测试文件原有条件跳过。TypeScript 无输出编译检查、浏览器脚本构建与差异检查通过。
- 在 Spark 隔离的 StageServer 和 Firefox 157.0.1 中同时打开声音、字幕与组合舞台，使用 1.520 秒的 Breeze WAV。实际音频播放器上报一次起播、一次结束，Stage 以同一语音 ID 确认结束。字幕页实际渲染对应文本，随后清空，透明样式生效。组合舞台没有收到这句音频，字幕源未收到音频载荷。
- Windows 隔离端口通过 SSH 转发验证两个入口可连接。直播姬 7.64.0.10819 的离线预览可查看，其管理员权限进程拦截普通权限工具的输入。直播姬自身的混音、本地录制及观众端声音尚未验证，本轮没有开播。

## 正式运行

首次验收时，正式 Web 3299 与舞台 3300 继续由原进程服务。因为同一 profile 里另有待加载的通话插件更新，先在隔离环境验证此次改动，并将安装目录中的八个共享文件断开硬链，维持在旧版字节。

用户确认切换后，等待正式通话结束，保留十个旧安装文件的备份，成套替换七个源码、舞台 CSS 和两个浏览器构建产物。按原入口重载 Web。新版 Web 正常加载原有会话，Spark 三个舞台入口均返回预期跳转。Windows 通过恢复的 3300 转发访问两个独立源和组合舞台，跟随跳转均返回 200。隔离通话预览的监听进程仍独立运行。

直播姬的场景需要用鼠标停用旧完整网页，再添加两个新源。完成后用一段本地录制验收字幕与音轨。需要回滚时成套恢复旧安装文件和构建产物，运行状态与会话数据无需迁移。
