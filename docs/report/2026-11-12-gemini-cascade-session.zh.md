# Gemini 3.8 Flash / Breeze：DSH 会话内通话试用

## 选择和范围

Spark 的 ElyHarn 主意识实际请求使用 D1 的 `deepseek-v4.1-flash`，不是这次的 Gemini。旧 Elysium 把 `gemini-3.8-flash` 经私有 NexusAI 模型网关转给启用的 A6API-Gemini 渠道 53。试用复用该路由，不改主意识、不更改渠道或凭据，不替换正式通话。没有另写 Breeze 推理。

新增 `plugins/gemini-cascade`，由原生 DSH Session 渲染语音控制和文字消息；新试用独立工作区和持久化 writer。浏览器经已有 DSH 认证取短效 LiveKit 房间令牌，服务端只接收当前试验房间的可信事件。Gemini 直接接收每轮原声，输出的文字送既有 Breeze 7865。没有录音、原声持久化、自动重拨、旧会话继承或公网监听。

## 证据

- 私有预览 DSH 已启动，回环 18795；正式 3299 保持运行。打开、开房、挂断接口返回 200，未认证打开返回 401，未授权事件入口返回 403。
- 以显式模拟 worker 事件验证 DSH 单写者：可信输入及完成事件返回 200；原生压缩会话记录含语音发言 notice 及测试助手文字，工作区注册含独立 Session ID。未发送用户麦克风音频或真实历史。
- 前端生产 bundle 和客户端严格类型检查通过。前端生命周期和协议 tests、host 输入契约以及 Python 离线测试见代码和运行结果；未修改上游 DSH。全仓级类型检查仍有既有 vendor 诊断，不能当成全绿。
- 两个真实 LiveKit SDK 参与者，模拟 Gemini 文字 + 真实 Breeze 音轨：正常一轮、中途插话、继续一轮，收到非静音帧 51 / 14 / 73。旧生成取消，待播清空，无旧完成事件。这不是实际用户浏览器或真实 A6 端到端。
- 网关健康和认证模型列表 HTTP 200；实际同一路由文字及原声请求未在探针等待窗口得到响应，原声最长一次 115 秒。网关近期通道 53 有 HTTP 200/数十秒耗时的记录，不能证明请求客户端收到了流式正文，也不能证明渠道已支持原声模式或实时响应。没有切换供应商、修改模型路由或降低 TLS 防护。

**尚未交付正式入口。** 需要 A6 完成一次无隐私的原声 → 文字流校验并测量首字，再在同一 DSH 会话实测三轮、插话和挂断。不能以模拟模型的成功替代 A6 验收。
