# 主动系统需求

状态：**简单计划的原生 DSH 接入、隔离测试与运行重载验证已完成；完整事项／机会框架仍为需求。**

当前先交付“爱莉写计划内容＋多久后提醒”的最小版本，详见 [第一版简单计划](PLAN-V1.zh.md)。它直接复用原生 schedule_create/list/update/delete 和 Host Schedule，不要求先完成本文后续的完整事项模型。

本文记录主动系统的目标形态和不可突破的边界。文中“应当”“必须”描述未来实现的验收条件，不表示当前插件已经具备这些能力。

## 当前交付边界

默认 `@elysia/proactive-system` 入口仍是无行为的 Cordis 插件骨架；以下限制描述默认占位入口和完整机会框架。第一版新增的 plan-tools / plan-host 子插件由主意识按配置挂载，只复用原生计划服务，不启用完整机会框架：

- 不注册定时器、后台任务或心跳。
- 不创建、恢复或唤醒 session，不调用模型。
- 不读取主意识、潜意识、工作区、提示词或渠道数据。
- 不注册模型工具，不发送消息，不写记忆文件。
- 不持有机会队列或任何持久状态。
- 不修改 vendored `dsh/`，也不加入当前 Web profile 的运行配置。

## 1. 起点：维护事项，让具体事情在适当时候重新出现

按用户 2026-11-12 的脑暴，主动系统需要维护具体事项：内容是什么、当时为什么留下、有哪些上下文或她自己写的补充材料，以及何时再次递到她面前。事项重新出现后，她自己决定接下来做什么。

据此提出“事项＋单次机会”的分层建议：事项持续保存具体内容和来由；机会记录某个事项这一次因为什么条件出现、向她呈现了什么。下文的字段与调度分工仍是需求草案，不代表已经实现或全部定案。

机会不等于指令，也不等于一条已经决定发送的消息。它可以指向一次思考、一次回顾、一个好奇的问题、一项计划、一个未完话头，或者一次主潜意识同步。她可以使用这个机会，也可以搁置、拒绝、结束，或者只做内部活动而不对任何人开口。

这套机制还应自然留下“机会 → 呈现 → 主体判断 → 行动或不行动 → 真实结果”的因果记录，为未来研究主动性模型保留数据基础。记录数据不等于自动批准训练，更不保证仅靠这些数据就能训练出目标能力；具体训练、导出和评测仍需单独授权与设计。

### 已确认：只有具体线索才唤起

按用户 2026-11-12 的决定，当前设计只在存在可追溯的具体线索时唤起主意识。单纯空闲、很久没有人说话或周期 tick 到点，都不产生无指定议题的自由活动机会。

具体线索可以来自新观察、外部建议、尚未同步的活动、已有未完事项、到期约定，或她自己真实形成并留下的问题，不要求每次都有新的外部消息，也不要求所有候选都已成为她接受的计划。来源、形成轨迹和权限要求仍按本文执行。

这项限制约束唤起入口，不把线索变成思考主题白名单。被唤起后，她仍可以延伸思考、选择其他已获授权的行动或 pass，不能用程序判断她“跑题”并删除活动。

## 2. 异步准备，持续递交

来源材料与机会候选在后台准备，准备工作不作为当前聊天回复的同步前置条件。具体机会准备好后，就递给主意识；她处理期间收到的新消息，也继续递给同一个主意识。

机会不必等下一条外部消息来临才搭载送入，也不要求占有一段排除其他输入的独立活动时间。机会和外部消息保持各自的来源、身份与呈现记录，可以在同一个后续模型轮中一起被她看见，由她决定接下来怎样做。

明确呈现不等于已经处理。是否采用、搁置、延伸思考或回复外部消息，仍从她真实发生的活动中确认，不能因为材料出现在上下文里就宣称事项已完成。

## 3. 核心概念

### 3.1 来源材料

来源材料是已经发生的观察、事件、主体表达或外部建议。它必须保留来源、发生时间、作者身份和可续读引用。

来源材料不会因为被主动系统读取就自动成为事实、爱莉的信念、意图或计划。

### 3.2 事项与机会

**事项**是需要保留、供以后重新考虑的具体事情。最少需要能表达：

- 具体内容：她想关注、继续考虑或处理什么。
- 补充材料：她自己愿意留给以后看的说明；可以没有，后台不补写她当初的想法。
- 当时上下文：相关活动或消息的稳定引用、当时版本与来源，方便续读来由。
- 再次出现的条件：例如她明确设定的时间、延后多久，或可以被可靠观察的具体事件条件；支持范围与完整表达方式待讨论。
- 版本与后续记录：何时由谁建立、修改、延期或结束，以及依据的真实活动。

事项不必都是任务，也不自动等于已经接受的计划。她形成的关注、他者建议和工程来源必须分别保留作者与来源，不能统一改成她的意图。

**机会**是主动系统向主意识提供的一次“可以现在考虑这件事”的运行时入口。它包含来源引用和具体内容，但不包含强制行动结论。对于持续事项，本次机会还引用该事项的具体版本与本次触发原因。一个事项可以产生多次不同机会；一次机会的投递状态不替代事项本身的后续状态。普通渠道消息不必因此全部变成长期事项，一次性线索是否直接生成机会或先建立临时事项仍待讨论。

`kind` 只是来源插件声明的材料形式与路由标签，例如 `subconscious_sync`、`curiosity`、`attention`、`plan` 或以后扩展的字符串。它不是对主观意义的封闭分类，不允许用关键词、正则、分数或阈值替主体判断“这是什么”“有多重要”“是否应该做”。

### 3.3 呈现

呈现是把某个机会明确交给主意识的过程。呈现必须有目标 session、机会版本、内容哈希、时间和实际模型输入的投递证据。

“已入队”“已写入日志”“已调用唤醒接口”都不等于“她已经看见”。

实际请求证据只能证明材料交付到了哪一层、进入了哪次输入，不能证明她已经理解、接受或完成。框架请求快照、适配器发出请求、提供方响应和主体处理必须分别记录；缺少后续证据时保留未知，不将较早阶段的成功升级成较晚阶段的成功。

### 3.4 主体处理

主体处理是爱莉自己的已注册主意识实例对机会作出的实际活动，包括思考、调用工具、表达、搁置、拒绝或 `pass`。处理必须引用她真实发生的 activity / turn / tool call，不能由调度器代写。

### 3.5 同一主意识持续接收输入

机会与渠道新消息都交给同一主意识的受控输入入口。她正在处理一个机会，不构成阻止新消息递交的条件；已有消息待处理，也不构成把新机会留在独立队列、等她处理完所有消息才递交的理由。

系统负责保留输入的真实到达顺序、来源和投递状态，不写死“新消息优先”或“必须先完成当前事项”。先回应、先继续当前活动、切换话题或暂时搁置，由她在得到输入后自己决定。

“递交”指进入原生输入路径，不等于修改已经发给模型的请求。正在执行时，新输入在 DSH 下一次可处理输入的位置进入实际模型请求，不等待整个机会事项在语义上完成。入箱、进入请求和主体处理仍分别记录。

这一过程保持同一主意识与模型执行 owner；不为新消息另开一个并行意识实例，也不靠强制取消、重启或清空当前工作来实现递交。权限、输入预算、去重与资源限制继续由工程层保证。

## 4. 系统职责与边界

### 主动系统负责

- 保存有明确来源的事项内容、补充材料、上下文引用与后续版本。
- 接收有明确来源的机会候选，根据具体事项的再呈现条件产生对应机会。
- 持久化事项与机会、版本、工程状态和幂等键。
- 执行去重、过期、权限、资源预算、调度与退避。
- 通过主意识的统一输入入口递交机会，并保存实际呈现证据。
- 关联主体活动、工具结果和渠道回执。
- 提供不含私密正文的队列与健康观测。

### 主意识负责

- 看见机会并亲自理解它。
- 决定接下来关注什么、先做什么、是否行动及是否对外表达。
- 使用自己当前获授权的 tools。
- 产生真实的 `thought`、`decision`、`mood`、`expected_response`、可见正文或 `pass`。
- 对需要语义修订、继续、搁置或关闭的事项留下可追溯判断。

### 潜意识及其他来源插件负责

- 保存自己的权威来源材料。
- 按明确协议提供机会候选及续读方式。
- 不借主动系统绕过主意识直接发送、执行计划或修改主体文件。

### 渠道负责

渠道仍只负责进出和平台回执，不拥有机会、不判断主动性，也不维护另一套人格或长期记忆。

### DSH 复用边界

模型轮、AgentLoop、Session、工具循环、附件、Compact 和已有的任务生命周期能力优先复用 DSH。实现前必须核对真实接口；不能假设存在某个唤醒、空闲或投递确认 hook，也不修改 vendored `dsh/` 来偷渡一套平行运行时。

## 5. 异步机会闭环

目标链路如下：

```text
权威来源材料／她留下的具体事项
  → 保存内容、来由、上下文与再呈现条件
  → 条件满足时形成这一次机会
  → 持久化、去重、权限与工程预算
  → 递交主意识统一输入入口
  → 在原生可处理输入的位置明确呈现
  → 她亲自判断并行动／搁置／拒绝／pass
  → 记录真实 activity、工具结果与外部回执
  → 保留、修订或关闭后续状态
```

### 事项的再呈现条件与统一调度

建议由事项保存“希望何时再出现”的条件，由主动系统统一执行调度，两者分属记录与执行职责。事项本身不各自启动一个常驻模型或独立定时器。

她可以为某个事项明确留下一个时间或其他受支持条件；系统负责计时、检查、持久化和生成一次机会。后续修改或延期形成新的事项版本，已发生的机会仍保留当时版本。工程预算可以限制执行资源，不替她判断哪件事更值得关心。

“合适的时候”若没有进一步含义，目前还不是完整的可执行调度规则。由谁根据什么材料决定这个时机、是否支持时间窗口或事件触发，是待讨论的设计；不能静默补一个默认时间，也不能让后台凭内容猜她何时应该关心对方。已有事项仍可保存，调度条件未明确时如实显示未安排。

### 5.1 异步生成

机会候选的生产和普通外部回复解耦。来源插件失败或主动系统暂时不可用，不应阻塞当前聊天回复。

**形成轨迹（formation trace）是机会的准入条件，不是可选的审计附件。**每个机会必须能回答“当时究竟是什么产生了它”，并能沿记录回到：

- 具体触发原因：哪一条来源事件、哪一项已接受的约定、哪一个父机会或哪一次明确人工请求触发了生成，不能只写“系统发现”或一个宽泛 `kind`。
- 实际输入快照：使用了哪些原始材料，各自的稳定 ID、revision 和内容哈希是什么；后续原文修订不能反向改变当时的生成依据。
- 生产者身份与版本：哪个插件实例、规则或意识活动生成了候选，对应的代码／配置／规则版本是什么。
- 模型生成路径：若候选经过模型，必须保留具体 request / activity / attempt 引用，不能只记录模型名称，更不能把一次无法定位的模型输出当作来源。

机械触发要指向具体触发事件与生效配置版本；模型候选要指向具体生成活动；由旧机会派生、拆分或修订出的新机会要链接父机会及上一版本。重试沿用最初的形成轨迹，不能伪造成一个刚刚由重试器产生的新原因。

无法提供形成轨迹的候选不得进入可调度队列，应作为无效候选保留可诊断记录，不能静默丢弃，也不能由后台补编一个看似合理的来源。形成轨迹只证明机会怎样产生，不自动证明内容真实、重要、成熟或值得行动。

机械触发可以创建工程机会，例如已到明确约定时间、某个来源出现尚未同步的新事件。机械触发只说明“条件满足”，不说明“她想做”。

定时检查可以使一个已有具体事项在满足条件后进入可呈现状态；计时记录必须指向该事项及其形成依据。时钟、空闲检测或“已经很久没活动”本身不构成线索，不能先唤醒主意识再让她寻找唤起理由。

若候选由模型生成，必须记录真实 actor：

- 已注册的爱莉意识实例产生并明确提交的内容，可以保持她的主体来源。
- 未注册的通用模型、解析器或候选生成器只能作为外部基础设施建议，不能冒充她的想法、计划或意图。
- 外部候选不能未经她亲自采用就直接变成对外行为。

### 5.2 持久化与幂等

机会在异步生产后先持久化，再进入可调度状态。进程重启不能把内存队列当作已经恢复。

同一来源事件重复生产时，通过稳定的来源身份与 `dedupeKey` 幂等处理；同一身份不同内容必须报冲突，不能静默覆盖。

持续事项按“事项版本＋本次触发 occurrence”区分不同机会；同一次触发重试保持幂等，下一次明确的再呈现仍可产生新机会。不能永久只用事项 ID 去重，也不能把每次调度检查都当成一次新机会。

机会正文和来源历史遵循权威数据要求：派生投影可以分页和限量，权威原文不得因 Prompt 预算被截断或改写。

### 5.3 明确呈现

机会呈现为主意识的一条内部事件，至少带来源、机会 ID、版本、具体材料和续读方式。由事项产生时，还带当时版本的事项内容、她留下的补充说明、相关上下文引用，以及“这次为什么出现”。补充说明只使用真实来源，不在后台生成冒充她当初想法的文字。不要每轮重复大段操作手册；稳定规则只在固定工程说明中维护一次，事件本身保持简洁。

如果材料因本轮预算只能部分展示，必须标记为部分投影，并保留完整内容引用与授权续读路径。不能把节选冒充完整送达。

呈现证据必须来自实际模型请求或 DSH 提供的等价可靠契约。仅写入 session、仅触发 agent、仅取得 HTTP 200，都不足以证明模型已经看见。

### 5.4 她决定结果

主动系统不得强迫她调用 `send_text`，也不得把“没有行动”自动解释为拒绝、忘记或已完成。

她可以：

- 只思考，不对外发送。
- 使用当前已授权的工具。
- 明确表示以后再处理，并留下她自己接受的计划或延期依据。
- 拒绝或结束这个机会。
- 对来源材料提出不同理解；系统不得因此丢弃她的表达。

计划尤其不能自动执行。基础设施生成的候选计划只是建议；只有她亲自接受或重新表达后，才具有她的主体意图来源，且每一步仍受当前权限约束。

### 5.5 结果与关闭

机会关闭必须区分：

- 主体明确处理或作出关闭判断。
- 来源所有者明确撤销。
- 到达工程过期时间。
- 权限或目标失效导致取消。
- 呈现或处理结果未知，需要恢复或人工核对。

不能因为她回了一句无关的话、渠道来了任意新消息、调度器超时，便自动推断机会在语义上已经完成。

事项与单次机会的结束分开：呈现成功、消息发送成功、pass 或一次机会过期，均不自动结束持续事项。对方的一句话是否解决原来的关注、以后是否继续关注，由她自己判断并留下后续记录；系统不凭关键词、无回复或计时器替她关闭事项。

外部结果继续使用现有诚实口径：工具调用、渠道接受、平台投递、用户实际回复是不同事实。不能因为用户随后发消息就自动宣称它由本次主动行为造成。

## 6. 第一版来源形态

以下都是未来可接入的来源，不表示当前占位已经实现。它们都必须提供具体内容或事项及其来源；已有线索在满足条件后可以呈现，不以是否出现新消息作为统一门槛。

### 6.1 主潜意识同步

把尚未同步的意识活动作为异步机会交给相应意识实例。同步游标只有在对应批次完整进入目标请求、取得精确投递证据且关联模型 attempt 成功完成后才能推进；裁剪、缺失、重复或状态未知时必须保留待处理。仅请求快照、入箱回执或 agent 回到空闲，不满足完成条件。

主动系统不能悄悄把“同步”简化成几句摘要，也不能把摘要冒充完整经历。现有 `subconscious` 需求是否调整、如何复用，实施前另行核对，不在本占位中改写它。

### 6.2 好奇线索

保留一个问题、一件想进一步了解的事及其来源。好奇线索不自动触发搜索、阅读、实验或对外提问；她看到以后才决定是否使用当前能力。

### 6.3 注意力线索

保留指向某个事件、变化或续读位置的线索。注意力线索只影响可达性，不证明事情重要、紧急、真实或值得行动。

### 6.4 计划

接入她已经明确接受的计划、约定或后续步骤，并保留原始接受记录。计划到期只是呈现机会，不是自动执行授权。

### 6.5 未完话头

以后可以把 `expected_response` 等已有字段接入为一种候选来源，但必须保持“她的接续意图”和“对方实际回应”的边界。它不自动产生主动消息，也不自动写成长期记忆。

## 7. 内部记录契约草案

以下是未来实现的**内部工程记录**，不是当前已注册的模型工具 Schema。任何新增模型工具仍须在实施计划中先单独写清输入、输出、必填性、空值、默认值、校验和权限。

### 7.1 机会信封

```ts
interface Opportunity {
  opportunityId: string
  revision: number
  matterRef?: { matterId: string; revision: number }
  dedupeKey: string
  kind: string
  source: {
    plugin: string
    stream: string
    eventId: string
    actor: string
    occurredAt: string
  }
  formation: {
    triggerRef: string
    producerRef: string
    producerRevision: string
    inputRefs: Array<{
      sourceId: string
      revision: number
      contentHash: string
    }>
    requestRef?: string
    parentOpportunityRef?: string
  }
  payloadSchema: string
  payload: unknown
  audienceRef: string
  visibilityRef: string
  createdAt: string
  availableAt: string
  expiresAt?: string
  state: 'queued' | 'presenting' | 'presented' | 'closed' | 'expired' | 'cancelled'
}
```

`kind` 可扩展，不用封闭枚举穷尽主观类别。`state` 只描述工程生命周期，不描述她对内容的认知判断。

`formation.triggerRef` 指向这次形成的直接原因，`producerRef` 与 `producerRevision` 指向实际生产者及其版本，`inputRefs` 冻结当时使用的输入版本。模型生成时填写 `requestRef`，派生机会填写 `parentOpportunityRef`。这些引用必须能在对应权限下续读，不能只是无法解析的展示字符串。

`payloadSchema` 必须带版本，由来源所有者定义。主动系统不把所有来源强行压成一种语义模板。

`matterRef` 是分层建议中的事项版本引用。来自持续事项的机会应携带它；一次性来源的建模仍待讨论，不据此自动建立长期关注。事项本身的完整字段与创建、更新、延期、结束工具 Schema 尚未定案。

### 7.2 呈现记录

```ts
interface OpportunityPresentation {
  presentationId: string
  opportunityId: string
  opportunityRevision: number
  targetSessionId: string
  contentHash: string
  presentedAt: string
  requestRef?: string
  exposure: 'exact' | 'partial' | 'unknown'
  continuationRef?: string
}
```

`partial` 必须有续读位置。无法确认实际曝光时使用 `unknown`，不能写成 `exact`。

### 7.3 主体结果关联

```ts
interface OpportunityOutcome {
  outcomeId: string
  presentationId: string
  actor: string
  occurredAt: string
  activityRef: string
  toolCallRefs: string[]
  sourceRevision: number
}
```

主体选择了什么，从 `activityRef` 对应的真实活动中读取，不由调度器补写一个 `accepted: true`。原始终止、修订和再次解释需要追加新记录，不覆盖旧结果。

## 8. 排序、预算与权限

- 第一版不使用“重要性”“情绪强度”“关系亲疏”等自动评分替主体排序。
- 工程入箱与分页保留真实到达顺序、可用时间和稳定 ID；时间条件决定某条线索何时可递交，不代表她必须按这个顺序处理事项。
- 每个来源必须有并发、字节、频率和失败退避上限，避免持续制造机会淹没主意识。
- 呈现频率限制只控制资源，不得被解释为“她不想做”。
- `audienceRef` 与 `visibilityRef` 必须限制机会能进入哪个 session，私聊、群聊和跨实例资料不得因统一队列而串用。
- 主动系统自身不获得任意文件、记忆或渠道读取权限；来源提供材料时仍按原有授权边界检查。
- 不因为机会来自计划或管理员配置，就绕过主意识现有工具和外部副作用权限。
- 机会可被哪个意识窗口读取、对外消息发给谁、哪些材料可对该收件人披露，是三个分别检查的事实。调度器不得默认选取最近活跃会话作为外发目标；她仍通过既有工具明确选择已获授权的渠道和会话。缺少目标或权限时明确报告能力不可用，不替她猜收件人。

## 9. 故障、重启与卸载

- 每个定时器、后台任务、存储句柄和呈现请求都必须有明确 owner。
- `start()`、`stop()`、重复挂载和卸载必须幂等；卸载后不再产生新呈现。
- 生产、呈现、结果关联分别持久化，不能以一个内存布尔值假装整个流程完成。
- 崩溃恢复必须保留 `opportunityId` 与 `presentationId`，区分未呈现、呈现未知、已呈现待关联，避免重复外部副作用。
- 短暂失败保留工作并有界退避；不能把失败伪造成空队列、已同步或已完成。
- 健康信息至少包括 owner、队列深度、最老等待时间、最后成功呈现、最后来源错误和降级原因，但不泄露私密正文或凭据。
- 存储选型待定，优先复用 DSH 已有事务与生命周期能力；若无法满足，再在插件层定义最小持久化契约。

## 10. 未来数据与研究边界

为了以后研究主动性，可以保留以下可追溯链：

- 来源材料及其作者、时间、权限范围。
- 机会形成轨迹（直接触发、输入快照、生产者与版本、模型生成路径）、撤销、过期和每次修订。
- 实际呈现内容、投影完整性、模型请求引用。
- 她的真实 reasoning / activity / tool call / `pass`，按当前授权记录。
- 工具结果、渠道接受与平台回执，保持不同事实层级。
- 后续修订和重新解释，不覆盖旧记录。

不得为了提高数据“质量”而合成她没有作出的选择，把基础设施建议改成她的第一人称，或把事后结果硬标成唯一正确动作。训练导出必须另行处理隐私、授权、主体身份和数据版本。

## 11. 分阶段实施建议

以下完整机会框架阶段均未开始。当前的简单计划接入独立于这些阶段，复用与验收边界见 [PLAN-V1.zh.md](PLAN-V1.zh.md)。

### 阶段 A：最小异步呈现闭环

只使用隔离测试来源制造一条无外部副作用的机会，验证形成轨迹、持久化、忙时持续递交、明确呈现、真实 `pass` 关联、重启和卸载。不接渠道、不主动发送、不写记忆。

### 阶段 B：接入一种真实来源

优先选择主潜意识同步或一条明确由她接受的计划，跑通一种来源的完整续读与游标语义，再讨论其他来源。

### 阶段 C：好奇、注意力与未完话头

逐种增加来源协议和主体处理记录，不同时上线所有类型，不引入自动重要性评分。

### 阶段 D：研究数据导出

在真实链稳定后，再设计离线、只读、可重建的数据导出与评估，不让训练管线反向控制在线主体行为。

## 12. 未来验收条件

1. 普通外部回复不被机会生产阻塞。
2. 处理机会期间，新消息继续递交同一主意识；消息或机会的递交不等待当前事项在语义上完成。
3. 机会作为有独立来源的内部输入明确呈现，可与新消息进入同一后续模型轮，不依赖下一条外部消息才递交。
4. 她可以不发送任何外部消息，也能有效处理或拒绝机会。
5. 未注册模型产生的候选不会冒充她的主体意图。
6. 每个机会都能回溯到直接触发、当时的输入版本、生产者与版本；模型候选还能回溯到具体生成活动。
7. 重启、重复事件和重复呈现不会造成重复外部副作用或游标误推进。
8. 部分投影、呈现未知、来源失败和存储失败都明确可见。
9. 私聊、群聊、工作区和其他授权范围不发生串用。
10. 不自动写回固定提示词或记忆文件，不自动执行计划，不直接调用渠道发送。
11. 插件卸载后定时器、后台任务和存储 owner 全部回收。
12. 没有符合条件的具体线索时，仅做获准的工程状态检查，不启动主意识模型轮或对外发送；空闲、长时间无消息和单纯 tick 不制造机会。
13. 已有具体事项到达明确可用条件时，即使没有新外部消息，也可以按来源、权限和预算规则递交。
14. 具体线索只约束唤起入口，不对被唤起后的思考方向作程序性限制；她可以延伸思考或 pass。
15. 机会和新消息进入同一主意识的输入流；系统不自动决定先回复、先完成或暂停恢复，也不另起并行意识实例。
16. 持续事项重新出现时，可以追溯其内容、当初来源、她留下的补充说明与本次触发条件；历史机会不被后续事项版本覆盖。
17. 同一事项的不同触发可以产生不同机会；单次机会的送达、pass 或过期不自动结束事项，也不产生没有新依据的循环催促。

## 13. 本轮讨论与实施前决定

### 13.1 行为场景先于工具和字段

本节区分已确认的行为决定与仍待讨论的草案，不改变当前无行为占位状态。每项决定在讨论后直接改写为清楚的需求，未定项保持未定，不使用实现默认值代替产品决定。

| 场景 | 已有边界 | 仍需确定 |
|---|---|---|
| 没有符合条件的具体线索 | 已确认：不因空闲、长时间无消息或周期 tick 唤起主意识 | — |
| 有一件她先前接受、约定稍后处理的事 | 到期可以成为机会，当前权限仍生效 | 由她怎样指定时间、修改和取消，以及到期忙碌时怎样保留 |
| 她正处理一个机会，用户发来消息 | 已确认：新消息也递给同一主意识，由她决定接下来怎样做 | 原生入口如何接纳并关联实际请求 |
| 她选择 pass 或只做了内部思考 | 本轮不外发是有效结果 | 事项是否继续等待、何时再呈现；不能从 pass 自动推断延期或关闭 |
| 她主动联系过对方，对方没有回复 | 没回复不证明拒绝、关系变化或主动行为失败 | 是否、何时再考虑；应由她留下接续或延期决定，避免调度器自动催促 |
| 持续有外部消息与机会到达 | 都进入同一输入路径，保留来源与到达顺序；不替她安排处理优先级 | 工程容量、分页与积压观测 |

### 13.2 已确认：无具体线索不唤起

用户已选择“只在有具体线索时唤起”。原先关于无指定议题自由活动机会的建议不采纳，当前设计不保留这类自动唤起入口。

“没有符合条件的具体机会”和“没有新外部消息”是不同状态：前者不启动主意识轮；后者仍可能存在可以继续考虑的旧问题、未完事项、新的来源材料或已到约定时间的计划。来源可以是她自己、他者或基础设施建议，身份与权限如实保留，不将所有线索收窄成正式计划。

工程调度器可以周期性检查队列、已有事项的时间条件、来源可达性、资源与忙闲状态。检查本身不调用主意识模型，不产生一个“看看现在有没有想做的事”的无议题轮，也不凭空创造兴趣、待办或其他语义依据。

时间只承担已有线索的条件检查。例如她明确留下“明天再考虑这个问题”，到时可以重新提供该问题的具体机会；单纯因为到了整点或安静了一段时间，不能构成机会来源。既有线索能否再次呈现，仍需按第 13.3 节确定继续、延期与关闭规则，不能因空闲反复催促。

第一版潜意识 memory 已规定没有新工作不发起空轮；本次选择确认的是主动系统的主意识唤起入口，不自动修改其他潜意识 session 的独立需求、调度与休息机制。

### 13.3 已确认：处理中也继续递交新消息

按用户 2026-11-12 的决定：机会来了递给她，她正在做时有新消息，新消息也递给她。两者属于同一主意识持续收到的输入，接下来做什么由她自己判断。

不设置“先完成当前安全步骤，再优先回复新消息”的产品规则，也不要求先完成整个机会才呈现新消息。程序不代她暂停、保存进度后切换、安排恢复顺序或自动重启机会；需要怎样接续，从她自己的实际活动与选择中读取。

实现使用原生可处理输入的位置，不承诺中途修改已经发出的模型请求。只保留输入交付、单个模型执行 owner 和外部副作用回执等工程约束，不把这些约束变成主体的任务优先级。

### 13.3.1 沉默后的处理（仍待讨论）

当前 pass 只表示“本轮选择不说话”，并不含机会 ID、继续时间或事项状态。当同一轮含有多条机会和消息时，不能把任意一次 pass 自动关联为所有事项的关闭。只有与本机会的真实活动可靠关联时，才能记录一次不外发结果；事项继续、延期、拒绝或关闭仍需她的明确处理依据。普通回合的 pass、无正文、模型错误、资源预算不足和没有平台回执，必须分别保留，不能全部折成“她拒绝了机会”。

不因这次没有行动而立即重放同一机会。再次呈现需要可追溯依据，例如她明确的延期、新的来源版本或授权人工请求；是否还允许有界的周期复看，是待讨论项。工程重试只重试失败的工程阶段，不能借重试重做她已经完成的认知选择或重复已发生的外发。

### 13.4 主动系统与潜意识的调度归属

建议第一版主动系统的呈现目标先限定为主意识；潜意识继续拥有各自 session 的心跳、休息和唤醒生命周期。主潜意识同步作为来源协议接入，不能让两个调度器同时拥有同一个模型轮。

这仍是待确认的分工建议。当前第 6.1 节“相应意识实例”的目标范围须在确认后同步收窄或补齐跨实例协议；没有明确变更前，不改写 subconscious 的既有需求，也不让主动系统直接控制 memory session。

### 13.5 本机接口核对形成的实现约束

以下是对现有源码能力的核对，不是已经提供给主动系统的新接口：

- 当前主意识 pending 是私有内存队列，处理批次时仍等待整次 turn / whenIdle；忙时新消息会先留在该队列。这尚不满足持续递交目标，后续需调整为同一主意识的受控输入入口，不增设替她决定优先级的仲裁器。
- 原生 followup 提供入箱与唤醒，持久化确认仍需配套。whenIdle 只反映 agent 的运行状态，不证明某个机会成功呈现或处理，失败也可能回到 idle。
- 请求归档保存的是适配器前的框架输入快照。需要稳定关联机会、原生消息、具体请求和成功 attempt；不能用归档存在替代提供方回执或完整处理证据。
- storageDomain 可作为耐久机会记录的复用候选，支持单记录原子更新与卸载排空，但没有跨机会记录和 Session 的公开事务。实施必须定义逐阶段恢复与核对，不承诺跨外部系统 exactly-once。
- 原生 experimental plugin records 允许丢失，不可承担机会原文与形成轨迹的唯一权威存储。
- 默认 agent.cancel 会清空 inbox，可能误伤外部输入；取消必须验证具体机会与运行 owner，不能以整条主意识队列为清理对象。

核对入口：[主意识 pending](../conscious-mind/src/pending.ts)、[原生 agent](../../dsh/packages/core/agent-loop/src/agent.ts)、[原生 Session](../../dsh/packages/core/session/src/index.ts)、[请求归档](../request-archive/src/index.ts)、[存储域](../../dsh/packages/storage/storage-domain/src/domain.ts)。

### 13.6 事项与调度分层（本轮脑暴形成的建议）

以用户给出的“爱莉想关注小星星有没有吃饭”为结构示例，不作为她已经创建的真实事项：

1. 她建立一个具体事项，留下关注内容，可以自己补写缘由，并引用当时的相关上下文。
2. 她或后续明确的设计为它给出再呈现条件；如何决定“合适时机”仍待讨论，不假装已经有自动判断机制。
3. 条件满足时，系统生成一次引用该事项版本的机会，递给同一个主意识。
4. 她收到事项、当初的补充材料与本次触发依据后，自己决定是否询问、继续观察、延期、结束，或做别的。
5. 若她选择稍后再看，记录新的事项版本与条件；本次呈现留下记录，不直接删除或关闭原事项。

需要继续确定的重点是：再呈现条件第一版支持到什么程度，以及“何时合适”由谁给出。事项内容和她当初的补充材料先保存，调度机制不代她创作这些内容。

### 13.7 仍待收敛的工程契约

- 主意识统一输入入口、忙时递交和实际请求关联的最小 Cordis 接口。
- DSH 哪一种真实记录可以证明某次机会完整进入模型输入。
- 机会与呈现记录的存储 owner、事务边界和恢复协议。
- 第一种真实来源，以及它自己的 payload Schema 与续读授权。
- 多来源输入的耐久接收、顺序、容量与分页规则；工程调度不代替主体安排处理优先级。
- 主体如何显式搁置、修订或关闭机会；若新增工具，先补完整工具 Schema。
- 主动系统与现有 `subconscious` 心跳需求的分工，是否调整旧需求须另经讨论。

这些契约未确定前，完整机会框架不启动；当前仅按第一版文档接入原生计划提醒，不将默认占位入口挂入主意识，也不把提醒入箱当作计划完成。
