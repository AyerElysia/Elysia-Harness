入站与出站是两条链路：工具只管出站
④ 入站覆盖本期要扩：10 种消息类型全收，非消息通知可查
现在只到 text / image
SUPPORTED_PART_TYPES = {text, image}； emoji/voice/file/video/share 一律标 failed， poke/system 根本不入队。
扩后：全部 10 种都到；语音/文件/视频只给元信息（听不见也读不了）。
通知：现在只广播给应用 UI
好友申请、群邀请、入群申请、帖子被评论……都进不了她的通道。 本期用 ayla_notifications 主动查（等价于人类看红点）； 要推送则后端加 type:"event" 帧。
REST 到此为止的部分 ≠ 用户看到的完整效果
⑥ 能力边界本期暂缓；工具必须如实返回「做到哪一步」
直播出画面 · 暂缓
:start 只写乐观标记 → SRS 仍查 idle。 要出画面需另有推流端向 rtmp://…/live/<stream_key> 推流。 本期直播间是黑的，工具返回带 streaming:false。
语音房出声 · 暂缓
join 只落成员表并下发 LiveKit token，音频不走 REST。 要出声需 LiveKit 客户端发布音轨。本期她只能在场 + 发文字， 工具返回带 audio:"unavailable"。
为什么左右两条路
消息投递不同（意识队列 vs 自建收件箱），但工具所到之处相同：三个主意识 session 都要能操作 Ayla。
为什么不做全局注册
潜意识 router、临时会话、子 agent 不该拿到「替她操作账号」的能力；作用域注册让能力与主体绑定。
为什么错误要翻译
403 可能是「不是群主」「被禁言」「不是好友」，三者下一步动作完全不同，笼统的「失败」等于没说。
