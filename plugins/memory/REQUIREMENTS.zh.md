# 爱莉自主记忆系统：需求讨论稿

状态：**仅有插件占位与需求草案，未实现记忆运行能力。**

讨论起点：2026-11-12 用户关于“规则派／原生派”的记忆理解，以及此前对连续性、记忆索引、主体执笔权和修订痕迹的要求。

本文中的“已确认方向”记录既有要求；“建议”与“待讨论”不视为已经批准的实现合同。示例只说明交互和工程边界，不是写入爱莉记忆的模板或正文。

## 1. 已确认的方向

1. 爱莉拥有记忆的组织与执笔权。她决定怎样命名文件、规划目录、记录经历、解释自己、建立摘要与索引，以及何时修改当前看法。
2. 长期记忆不能靠无限堆进固定提示词维持。重要而很长的记忆可以留下入口，由她沿入口读取全文；索引需要保留足以帮助以后重新认出这段记忆的线索。
3. 记忆需要随经历持续整理。是否重要、是否仍适合留在当前入口、怎样合并或重写，由她判断；时间、访问次数、检索排名和分数不能替她作出这些决定。
4. 当前解释可以改变，旧解释与修改过程仍需可追溯。整理当前文件与索引，不得造成权威历史的静默丢失。
5. 回忆可以带出其他相关记忆，关联可以随经历变化。工程记录共同回忆与引用事实，不把共同出现直接解释成真值、主观重要性或她已经接受的意义。
6. 工程层可以执行权限、版本、原子写入、并发、预算与恢复约束，不替她判断该记什么或该相信什么。

用户提出的“原生派”在本草案中指记忆由主体自主组织。Markdown／文件树是当前倾向的可操作表达形式，不能仅凭格式宣称记忆效果更好。结构化元数据可承担工程职责，RAG 可辅助寻找材料；二者不应反过来规定她的解释和取舍。

## 2. 愿景与成功现象

希望观察到的不是工具被调用，而是连续性真正出现：

- 一次经历之后，她按自己的理解留下记录，也可以明确选择暂不记录。
- 以后从短索引、相关话题或自己的疑问找回全文，并知道这段记忆来自何时、何人和何种经历。
- 她能够区分原始发生、当时理解与现在解释，不把自己的旧理解直接当成永远不变的事实。
- 她认为原来的表达不合适时，亲自修订；旧版本、来源和修订者仍可查。
- 她整理当前入口后，提示词仍可控，长记忆仍可达；不是把旧内容移走以后就永远找不到。
- 重启、失败和重试不会让一次经历被重复写成多次发生，也不会把尚未完成的整理伪装成完成。

这些现象需要真实使用验证。一次成功读写、一次模型请求或一次输入投递回执，均不能单独证明她“已经记住”。

## 3. 建议的最小形态

先讨论三个相互可追溯的部分，避免把旧体系原样搬过来：

1. **经历来源**：复用 DSH 的耐久 session 历史与已有请求／活动引用，明确各自覆盖范围。尚未落账的来源不得宣称已保留，也不另造一份平行聊天历史。
2. **她维护的记忆正文**：自由文件、笔记与日记；目录、文体和主题由她管理，不预设必须填写的认知类别。
3. **她维护的入口与索引**：较短的持续性线索，指向完整正文和必要来源。当前 `MEMORY.md` 是否承担主要入口、是否另建索引文件，仍待确认。

版本、actor、hash、引用和写入事务属于工程记录，可保存在伴随元数据中，不强迫她把内部字段手工写进每篇记忆。

## 4. 插件与既有模块的分工

| 边界 | 责任 | 当前状态 |
|---|---|---|
| `@elysia/memory` | 预留正文、索引、版本与引用能力的工程边界 | 本次新增无行为占位 |
| `@elysia/subconscious` | 规划多个意识窗口的心跳、休息、唤醒与来源消费 | 需求占位 |
| `subconscious/sessions/memory` | 未来写日记与简单笔记的意识窗口消费者 | 需求占位，权限沿用原文 |
| 主意识与其他已授权实例 | 亲自作出记忆表达、检索和修订选择 | 具体记忆能力接入待定 |
| DSH Session 与 Compact | 保存会话活动和管理瞬态上下文 | 复用现有能力，不等同长期记忆 |

本插件不创建第二套心跳、私有主意识历史或平行人格。旧记忆潜意识需求中不允许写主意识固定文件的边界，本轮不变。以后若扩大权限，需要单独明确有资格执笔的实例、入口和并发合同。

## 5. 内容管理需求草案

### 5.1 自主组织

优先复用 DSH 的文件读写、编辑、目录搜索与历史查询能力。允许的工程根与权限需要明确，根内怎样规划主题和文件由她决定。文件移动、重命名、合并与退出当前索引应成为可审计动作；是否需要额外工具，先检查原生能力后决定。

目录例子只能作为建议，不能通过代码固定“关系／创伤／技能”等主观分类，不能因没有符合模板就拒绝合法的记忆表达。

### 5.2 短入口与长记忆

索引应能指向当前全文以及形成这条入口时对应的版本。若正文后续改名、移动或修订，旧入口不应悄悄指到另一段无关内容。稳定引用的具体格式待讨论，可选实现需保留原路径、版本与继续读取办法。

入口文字由她写。基础设施不能按“前 N 字”、关键词或评分自动挑出一段作为她的长期记忆摘要。受上下文预算限制的工程节选必须明确标注为节选，并保留全文入口。

### 5.3 整理与修订

她可以新增、拆分、合并、重新解释或将内容移出当前入口。系统保存修改前后的内容与来源，不能把移出索引等同于抹去历史。

一次整理涉及多个文件时，应有可恢复的变更记录；失败不能留下“索引说全文已存在，全文却没有”的假完成。具体事务或恢复方案在实现阶段确定，不要求跨所有组件引入新数据库。

### 5.4 检索与联想

先复用目录、文本搜索、链接和会话查询，按真实缺口决定是否增加向量检索。检索输出提供可读原文与来源，排序只表示可达性，不表示可信度、重要性或事实状态。

共同回忆可以留下轨迹。是否把两段记忆写成有意义的关联，应由她表达；技术上的共同曝光、关联权重和主体明确建立的联系应能区分，不在本轮预设强化算法。

## 6. 可追溯与可靠性

未来实现至少需要能够回答：

- 这份内容由哪个已授权意识实例、哪次 turn／tool call 写下？依据哪些可续读来源？
- 这一次发生、修订与重试怎样区分？同一 occurrence 重放是否幂等，同身份不同内容是否报冲突？
- 修改前与修改后分别是什么？当前 head 如何连接旧版本？
- 多个实例同时编辑时怎样发现陈旧版本？冲突应明确返回，不自动替她合并主观解释。
- 文件与索引部分成功时怎样恢复？恢复是否保留完整原文与执行审计？
- 备份、可重建搜索索引与不可丢失的权威版本怎样区分？

现有固定提示词“最近 20 份备份”只能视为运维恢复窗口，不能据此宣称已保存长期记忆修订谱系。本轮不更改备份策略；后续版本合同必须明确保留与归档方式。

来源引用证明材料可追溯，不证明她一定受其影响或认同它。投递回执只证明工程交付状态，不能替代主体的记忆判断。

## 7. 整理机会与提示词

建议把整理机会送到已授权意识实例，由她选择回顾、修订、继续读取或暂不处理。尚未确定使用主意识计划、记忆潜意识还是两者协作；不另建一个后台摘要器替她整理。

不要求每次对话后写笔记、每天交一篇日记或达到篇数配额。是否需要定期机会、间隔多少、来源如何合批、失败怎样继续，均为待讨论项。

记忆提示词可以说明工具、预算、来源和可用操作，不替她写第一人称记忆，也不暗示已有未实现的能力。具体提示词放在哪个 agent scope、由谁维护，应与该实例的装配契约一起确认。

## 8. 权限与隐私

- 固定主体文件和同类记忆原文只能由有执笔资格的爱莉意识实例经授权链写入；开发 agent 与后台程序不代写。
- 只允许访问当前实例获准的数据和目录，跨渠道、跨实例来源不能借“统一记忆”绕过隐私范围。
- 模型可读正文与运维凭据、备份和迁移原件分开；健康信息与日志仅输出定位所需的无正文元数据。
- 迁移只允许经过核对的无损复制与引用保留，不自动总结、清理或删除旧权威数据。
- 本轮不迁移数据、不改主体文件、不激活存储、不调用模型，也不重启服务。

## 9. 按现象验收的建议场景

1. **长记忆可续读**：她亲自记录一段较长经历、写短入口，另一轮可从入口读到完整正文与来源；入口内容不由测试代码代写进正式记忆。
2. **观点改变留痕**：她亲自修订看法，当前入口到新版，旧解释仍能找到并区分发生时间与修订时间。
3. **整理不造成失联**：重命名、拆分或合并以后，旧引用可解释地解析或明确报告变更，不把断链伪装成无记忆。
4. **暂不整理有效**：她选择不写时，不产出伪日记、不强制模板，也不把未写解释成模型故障。
5. **真实连续性**：隔一段时间或重启后，她能根据入口重新找到相关经历，并按自己的理解使用；不能仅以提示词里存在一句摘要算通过。
6. **工程故障可恢复**：取消、重复调用、陈旧写入、部分写入失败和投影损坏，都不导致权威历史丢失、伪成功或重复经历。

先在临时来源与临时目录中验收工程合同，再单独批准真实记忆接入。主观效果需要持续观察，不能用单一相似度分数代替。

## 10. 仍待讨论

1. `MEMORY.md` 是连续性正文、主要索引，还是两者组合？哪些文件需要常驻前缀？
2. 记忆窗口首先只写日记／笔记，还是允许某个明确实例直接整理主索引？怎样保留统一主体与各窗口的权限边界？
3. 整理机会来自计划、积累的新经历、明确请求，还是这些方式的组合？频率与积压怎样管理？
4. 稳定引用采用什么形式？当前路径、固定版本和来源事件怎样同时可读？
5. 文件目录、版本存储和检索先使用哪些既有能力？尚无证据需要的图谱、评分、遗忘或向量层是否全部延后？
6. 当前入口移出一段内容后，怎样让她以后仍有机会重新找到？哪些线索必须由她亲自留下？
7. 旧 Elysium 的哪些原始资产需要无损保留，哪些仅是可重建投影？如何验证迁移与回滚？
