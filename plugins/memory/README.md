# Memory

`@elysia/memory` 是爱莉自主组织记忆的工程插件占位。

目前没有运行能力：不创建 session、不启动心跳、不调用模型、不注册工具、不扫描或读写文件，也没有接入当前 Web / TUI profile。`cordis.patch.yml` 只预留可显式挂载的无行为插件行。

## 设计方向

爱莉亲自组织记忆正文、文件树、摘要、索引和修订。工程层为未来的读写、版本、来源、检索和恢复提供保障；不依据分数、时间或固定类别替她判断重要性、解释或遗忘。

Markdown 文件与索引是当前讨论的主要表达形式。数据库或搜索引擎可以承担底层版本与检索，不因此拥有主观语义的决定权。尚未确定目录模板、固定字段、整理频率或检索后端。

完整草案：[REQUIREMENTS.zh.md](REQUIREMENTS.zh.md)。文档区分已确认方向、实现建议和待讨论问题；占位不代表闭环已经实现。

## 与潜意识宿主的关系

- `@elysia/subconscious` 规划 session 的唤醒、休息、调度与来源消费。
- 本插件预留记忆内容、引用与修订能力的工程边界，不再创建第二套记忆 session 或调度器。
- `subconscious/sessions/memory` 中现有“写日记与简单笔记”的需求保留为未来消费者，不因本次占位而自动启用或改变权限。
- DSH 继续拥有 session 原始历史与通用工具。Compact 与长期记忆整理是不同操作。

## 占位验证

依赖已按仓库工作区安装后，从 `dsh` 运行：

```sh
pnpm --filter @elysia/memory test
```

测试只验证占位不取得宿主能力，以及可挂载、卸载与再次挂载；没有调用模型或正式数据，不证明任何记忆功能已经可用。
