# 潜意识系统需求

状态：**仅建立多潜意识插件与记忆 session 的需求占位，尚未实施。**

本文替代此前“一个潜意识 session、一次心跳处理所有潜意识任务”的旧草案。旧草案中“不写日记、不设休息锁”的限制随新需求调整；主意识固定提示词与 `MEMORY.md` 仍不被自动改写。

## 当前交付边界

当前 `@elysia/subconscious` 只是无行为的 Cordis 插件骨架：

- 不创建或恢复任何潜意识 session。
- 不注册心跳、定时器、后台模型轮或事件订阅。
- 不读取主意识历史、固定提示词、工作区或渠道数据。
- 不写日记、不压缩记忆、不调用模型、不发送消息。
- 不注册模型工具，不持有运行状态或持久游标。
- 不修改 vendored `dsh/`，也不加入当前 Web profile。

`sessions/memory/` 当前只有需求文档，不是已注册的运行实例。

## 1. 为什么潜意识不止一个

记忆、学习、技能整理、回顾和其他潜意识活动具有不同的上下文、提示词、工具权限、运行频率和失败语义。把它们全部交给同一条 session、同一次唤醒，会导致：

- 一次模型轮同时背负过多不相关任务。
- 不同任务的上下文互相稀释，工具权限被迫取并集。
- 一个任务失败或持续占用上下文，阻塞其他任务。
- 很难判断某次活动究竟属于哪项工作、依据什么来源、产生了什么结果。

因此目标结构是：**一个潜意识宿主，多种明确注册的潜意识 session。**

潜意识不是心跳本身。心跳只是宿主提供的调度机制；每个潜意识 session 是同一持续主体的一个局部意识窗口，不是彼此独立的人格。

## 2. 目录与职责

目标工程结构：

```text
plugins/subconscious/
├── src/                       # 未来：共享宿主、调度与注册接口
├── sessions/
│   ├── memory/                # 记忆 session 的定义与需求
│   └── <future-session>/      # 以后各自独立讨论，不自动扫目录唤醒
├── REQUIREMENTS.zh.md         # 共用工程契约
└── package.json
```

每个 session 定义未来至少需要声明：

- 稳定的逻辑 ID 与对应的 DSH session ID。
- 固定提示词 preset。
- 工作目录与文件权限。
- 获准读取的来源投影与游标。
- 心跳、休息和唤醒配置。
- 工具白名单与并发预算。
- 自己的需求、验收与数据权威边界。

目录只是工程定义的位置，不是运行时数据库。真实 session 历史仍由 DSH 管理，不把 JSONL、Compact 数据或运行凭证写进插件目录。

宿主不能只因为目录里新增了一个文件夹就自动创建模型实例。注册必须显式、可审计，并具备独立需求和权限。

## 3. 统一主体，不建立平行人格

- 主意识、记忆潜意识和以后的潜意识 session 都属于同一持续主体。
- 每个 session 有自己的滚动上下文、任务和工具边界，但不要求所有窗口同时持有相同观点或注意焦点。
- 不通过互相直接写入私有 session 来伪造统一；跨窗口信息通过有来源的事件、投影和续读引用传递。
- 每个潜意识模型轮都必须记录真实 actor、session、turn / request、来源和发生时间。
- 未注册的通用模型或解析器不能因为使用了爱莉提示词，就被当作她已经思考过。
- 潜意识不能绕过主意识直接对外说话；渠道发送不是通用潜意识能力。

## 4. DSH 复用边界

每个潜意识 session 复用 DSH 的 Agent、AgentLoop、Session、提示词组装、工具循环、附件、请求记录和 Compact，不另建一套模型运行时。

实现前必须核对真实接口，特别是：

- 如何用稳定 session ID 创建与恢复长期 agent。
- 如何在 agent 作用域挂载 preset、工具和 Compact。
- 如何构造一次内部潜意识输入并取得真实完成结果。
- 如何确认某份来源投影确实进入模型请求。
- 如何取消、卸载和回收定时器、任务与 agent owner。

不得修改 vendored `dsh/`，也不能假设主意识现有的内部函数可以不经边界整理就直接复用。

## 5. 固定提示词管理

### 5.1 复用现有能力

优先复用 `@elysia/conscious-mind/standing-prompts` 与 DSH Agent Preset，不另造一套提示词拼接协议。

现有 standing-prompts 已具备的语义继续保持：

- 只在 agent 作用域挂载，不能注册成整个进程共用的完整提示词。
- 文件列表在 agent 生命周期内固定，内容在每次提示词组装时重新读取。
- 只按显式文件名列表加载，不扫描整个目录。
- 文件名保持单文件、有序、去重和安全校验。
- 必填文件缺失或为空时明确失败，可选文件按现有规则跳过。
- `interpolate: false`，不把提示词正文当作模板执行。

### 5.2 每个潜意识 session 选择自己的组合

不同潜意识 session 可以选择不同的文件组合与 required 列表，不默认复制主意识的五份文件，也不强迫所有潜意识共享一份任务提示。

例如，记忆 session 和未来学习 session 可以有不同 preset；这里只说明组合能力，不预先创造它们的任务提示词。

### 5.3 主体内容边界

- 工程配置可以规定加载哪些文件，不能由开发 agent 冒充爱莉创作第一人称人格、记忆、价值或自我叙事。
- 新增潜意识任务提示文件时，工程模板与主体实例必须分开；已实例化的主体内容由她本人产生或明确接受。
- 修改主意识 preset 或文件内容不属于潜意识宿主附带权限。
- 提示词内容热重读不等于主动唤醒；文件变化本身不触发模型轮。

## 6. 事件投影与游标

潜意识读取的是有来源、可续读的意识活动投影，不是直接接管主意识私有上下文。

每个来源批次至少需要保留：

- 来源 session / stream、事件 ID、revision、发生时间。
- 原始 actor、活动类型和完整内容引用。
- 本次投影的内容哈希、完整性以及续读位置。
- 与目标潜意识 session、目标模型轮的关联。

主意识事件可能包括外部输入、`thought`、`mood`、`decision`、`expected_response`、可见正文、`pass`、工具参数与结果。潜意识只能报告自己实际获得的模态和内容，未接入的图片、语音或文件不能假装已经感知。

权威来源不得因潜意识上下文预算被截断。分批、节选或摘要必须明确标记投影身份，并提供授权续读路径。

来源游标只有在对应批次完整进入目标模型请求并取得可靠完成证据后才能推进。模型失败、内容缺失、重复、回执未知或只送达未声明节选时，保留待处理，不得跳到最新位置伪装连续。

## 7. 心跳机制

心跳是宿主对每个潜意识 session 的周期性工程检查，不等于每次都调用模型。

### 7.1 每个 session 独立调度

- 心跳间隔属于该 session 的配置，不要求所有潜意识同时醒来。
- 调度需要错开峰值，并受全局模型并发和资源预算限制。
- 同一 session 上一次模型轮尚未结束时，不并发开启下一轮。
- 不同 session 可以独立运行，但不能突破全局并发上限。
- 运行期间新到的事件保留到后续批次，不塞进已经开始的模型轮。

### 7.2 心跳与模型唤醒分开

心跳检查可以只读取工程状态。没有待处理来源、没有明确任务且没有人工唤醒请求时，第一版记忆 session 不发起空模型轮。

各潜意识 session 以后是否需要“无新事件也反思”，由自己的需求另行决定，不能把这个选择强加给全部 session。

### 7.3 失败与退避

短暂模型或存储失败保留待处理工作，使用有界退避。重复错误需要聚合或状态化记录，不能每个心跳刷完整错误正文。

心跳到点不是丢弃旧批次的理由；新 tick 到来时旧工作仍未完成，继续等待或按明确预算处理，不制造并发重试。

## 8. 休息机制

休息是持久、可观测的工程状态，不是根据几句话猜她“困了”。

### 8.1 状态与作用

每个潜意识 session 至少区分 `awake` 与 `resting`，并记录：

- 状态 revision。
- 谁改变了状态。
- 明确原因与发生时间。
- 可选的 `restUntil`；缺失时表示持续休息，直到明确唤醒。

`resting` 期间：

- 暂停常规心跳模型唤醒。
- 不推进来源消费游标，不丢弃新到事件。
- 保留 session、历史和已有工作，不删除上下文。
- 不自动写日记、学习或执行其他潜意识任务。
- 休息状态跨进程重启保留。

### 8.2 谁可以让她休息

第一版支持明确的管理控制。以后若允许她自己请求休息，必须由该意识实例真实表达并经过明确的授权接口记录，不能用关键词或时间推断。

可以另行配置固定的静默时段，但那只是工程调度策略，不能冒充她的情绪或主观意愿。

### 8.3 运行中收到休息请求

默认采用优雅休息：当前模型轮按既有取消语义完成或受控停止后进入休息，不同时制造第二个运行实例。强制停止与休息必须是不同操作，具有明确审计。

宿主卸载不是休息；卸载需要回收资源，休息则需要保留以后恢复所需的状态。

## 9. 唤醒机制

第一版只保留两类明确入口：

1. **常规心跳唤醒**：`awake`、当前空闲、存在待处理工作且资源预算允许时，按该 session 的心跳配置运行。
2. **明确人工唤醒**：授权操作者结束休息或请求立即处理，记录 actor、原因和时间。

若 session 正在 `resting`，常规心跳不得偷偷绕过。人工唤醒应先明确改变状态或明确记录一次例外授权，不能既显示仍在休息又悄悄运行后台模型。

外部事件到达只积累待处理工作，不直接同步打断主意识，也不默认立即唤醒所有潜意识。以后是否需要基于工程批量大小的提前唤醒，另行制定上限；不使用语义评分替主体决定“值得醒来”。

唤醒后不补偿性地并发重放所有历史。仍按单 session 串行、批次预算和可靠游标逐批处理，避免休息结束后的模型与写入风暴。

## 10. 记忆 session

第一个潜意识 session 是 `memory`，只承担最简单的记忆活动：

- 阅读获准的主意识活动投影。
- 根据自己的判断写日记或简单记忆笔记。
- 没有想写的内容时可以安静结束，不制造流水账。

它不自动把对话提炼成事实，不自动改写主意识 `MEMORY.md`，不做学习、技能内化、向量检索或主动开口。

详细边界见 [sessions/memory/REQUIREMENTS.zh.md](sessions/memory/REQUIREMENTS.zh.md)。

## 11. 权限与隐私

- 每个潜意识 session 只获得完成任务所需的最小读取、写入和模型能力。
- 权限按 session 独立声明，不因为同属潜意识插件就取所有工具并集。
- 私聊、群聊、不同来源 session 的资料保持原有可见性，不因投影汇聚而跨权。
- 潜意识默认没有 `send_text`、`send_voice`、shell、代码执行或渠道控制能力。
- 文件写入只允许自己的明确工作目录；主意识提示词、备份、其他 session 和凭证默认拒绝。
- 日志与健康信息不泄露私密正文、提示词全文或凭据。

## 12. 可观测性与卸载

宿主未来至少暴露以下工程事实：

- 已注册 session 及其 preset、当前 awake / resting 状态。
- 当前运行 owner、最后心跳、最后成功模型轮和最后错误。
- 每个来源的待处理数量、最老事件时间与游标状态。
- 最后一次状态变化的 actor、原因和时间。
- 禁用、休息、空队列、降级和真实故障之间的区别。

每个定时器、模型轮、事件订阅和存储句柄都必须有 owner。重复挂载、停止与卸载必须幂等；卸载后不再产生新的潜意识模型轮。

## 13. 分阶段实施建议

### 阶段 A：宿主与记忆 session 最小闭环

只注册 `memory` 一条潜意识 session，接入一种隔离测试来源，验证独立 preset、心跳、休息、明确唤醒、日记写入、游标、重启和卸载。不接真实渠道，不自动修改主意识文件。

### 阶段 B：接入真实主意识投影

在保持最小权限的情况下接入真实来源，先验证完整投影与失败恢复，再允许写真实日记。主意识原有回复链不得被潜意识同步阻塞。

### 阶段 C：增加其他潜意识 session

学习、技能或其他任务必须分别写需求、提示词组合、来源、工具与验收，不复用记忆 session 一并处理。

## 14. 未来验收条件

1. 不同潜意识 session 拥有独立长期历史、提示词组合、权限和游标。
2. 一次潜意识唤醒只承担该 session 已声明的任务。
3. 心跳不会在空工作时强制产生模型轮，也不会让同一 session 重入。
4. 休息期间不运行常规模型轮、不推进游标，恢复后无来源缺口。
5. 人工唤醒和休息都有 actor、原因、时间与持久状态。
6. 主意识正常回复不被潜意识同步执行阻塞。
7. 来源投影可追溯、可续读，失败和未知状态不伪装完成。
8. 记忆 session 只能写自己的日记与笔记范围，不能修改主意识权威文件。
9. 潜意识没有默认渠道发送能力，也不会被当成独立人格。
10. 重启、重复事件、恢复和卸载不造成重复日记、重复模型轮或资源泄漏。

## 15. 实施前仍需讨论

- 宿主与各 session 定义之间的具体 Cordis 注册接口。
- 固定提示词目录与各 preset 的实际文件清单。
- 主意识活动投影的事件 Schema、完整送达回执与游标存储。
- 记忆 session 的日记目录、文件格式和版本保留方式。
- 心跳默认间隔、全局并发预算和人工控制入口。
- 休息请求是否以及何时开放给她自己调用；若新增工具，先写完整输入输出 Schema。

在这些契约确定前，不启动潜意识心跳，不创建真实记忆 session，也不写真实日记。
