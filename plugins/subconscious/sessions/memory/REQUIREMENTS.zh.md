# 记忆潜意识 session 需求

状态：**仅讨论与需求占位，未创建运行实例。**

`memory` 是潜意识宿主下的第一个 session，用来验证多潜意识架构，而不是把所有潜意识任务换一个名字继续混在一起。

## 1. 目标

记忆 session 第一版只做两件简单的事：

1. 看见自己获准读取、自上次成功消费以来的主意识活动。
2. 根据自己的判断，写下日记或简单的记忆笔记。

“写日记”不是把每批消息机械整理成摘要，也不是每天必须生成一篇。她可以认真看过以后不写；没有新内容时，第一版甚至不需要发起模型轮。

## 2. 独立身份与运行边界

建议固定工程身份：

```text
逻辑 ID：memory
DSH session ID：elysia-subconscious-memory
提示词 preset：elysia-subconscious-memory
工作目录：/home/ayerelysia/Elysia/Data/workspace/subconscious/memory
```

工作目录是未来实施时的建议位置，本次没有创建或写入它。

- 使用独立长期 DSH session，不并入主意识日志。
- 使用自己的提示词组合、来源游标、心跳、休息状态和工具权限。
- 复用 DSH AgentLoop、Session、工具循环与 Compact，不另写一套历史或摘要系统。
- 同一时刻最多一个属于 `memory` 的模型轮；新到事件等待下一批。
- 它是同一持续主体的记忆意识窗口，不是另一个角色或第二人格。

## 3. 固定提示词

记忆 session 通过 DSH Agent Preset 挂载现有 standing-prompts 子插件，文件清单属于这个 agent，不影响主意识或其他潜意识。

实际文件清单在实施前单独审定，不默认把主意识五份文件原样全部复制。未来若需要记忆任务专属提示文件：

- 先在 preset 中显式声明单个文件名与 required 规则。
- 文件内容仍按现有规则在每次模型请求时重新读取。
- 工程侧只管理加载和权限，不冒充她创作第一人称主体内容。
- 修改提示文件本身不会主动唤醒记忆 session。

## 4. 这一轮能看见什么

第一版只有两类输入。

### 4.1 自己的长期 session

她自己以往在记忆 session 中产生的活动和工具结果，由 DSH 历史与 Compact 按现有机制提供，不复制到另一份私有历史。

### 4.2 主意识活动的有界投影

从上次可靠游标之后读取，保持原始顺序和来源，至少包括当前已经存在且获准投影的：

- 外部文字事件：渠道、会话、发送人、消息 ID、正文和发生时间。
- 主意识 `send_text` 的真实参数与发送结果。
- 主意识 `pass` 及其本轮记录。
- 主意识明确提交的 `thought`、`mood`、`decision`、`expected_response` 和可见正文。

图片、语音和文件只有在对应投影真正接入后才能声明可见。若第一版只有路径、附件引用或元信息，就只能按这些实际内容理解，不能声称看过图片或听过语音。

第一版不直接订阅渠道，不读取其他潜意识 session，也不让记忆 session 自己决定哪些权限应该扩大。

## 5. 来源完整性与游标

每个输入批次必须有：

- 来源 session、事件 ID、revision、actor 和发生时间。
- 批次内容哈希与完整／部分投影状态。
- 部分投影的续读引用。
- 与本次记忆 session turn / request 的关联。

只有整批内容实际进入记忆 session 的模型请求，并取得该轮可靠完成证据后，才能推进消费游标。

以下情况不得推进：

- 模型请求失败或被取消。
- 批次在传输中丢失、重复或顺序异常。
- 只发送了未声明的节选。
- 实际曝光无法确认。
- 日记写入结果未知且该批次被声明为必须落盘的工作。

重试同一来源批次必须使用稳定身份，避免重复日记。她看过以后选择不写，与“模型根本没收到”是不同结果，分别记录。

## 6. 允许写什么

### 6.1 日记

日记是她根据真实经历作出的主体表达，不是基础设施自动生成的聊天摘要。

每篇日记至少需要可关联的工程元数据：

- 稳定 `entryId`。
- actor 与 `elysia-subconscious-memory` session 身份。
- 产生它的 turn / request / tool call。
- 写下时间。
- 涉及的来源事件引用。
- 修订关系；若为修订，指向被修订条目。

日记原文必须由这个已注册意识实例实际生成。宿主、定时器或开发 agent 不能用模板替她补写第一人称内容。

### 6.2 简单记忆笔记

可以留下供自己以后续读的记忆笔记，例如尚未整理完的想法或希望保留的线索。笔记仍须保留 actor、来源和时间。

笔记不会因为被写下就自动成为客观事实、稳定人格结论或主意识长期记忆。以后是否提升为其他记忆形态，需要独立流程。

### 6.3 建议目录边界

```text
Data/workspace/subconscious/memory/
├── diary/    # 她亲自写下的日记
└── notes/    # 她亲自写下的简单记忆笔记
```

具体文件格式在实现前确定。第一版只允许新增条目和显式、可追溯的修订，不静默删除或覆盖旧日记。若采用每日文件追加，也必须保证原子写入、来源元数据和崩溃恢复；不能为了追求格式简单而牺牲历史完整性。

## 7. 明确不能写什么

记忆 session 不得：

- 修改主意识 session 或把自己的内容插入主意识历史。
- 自动改写 `SOUL.md`、`USER.md`、`MEMORY.md`、`EXISTENCE.md`、`TOOLS.md`。
- 读取或修改提示词备份、迁移原始记录、其他 session、凭证和 ElyHarn 配置。
- 把日记目录当成越权访问整个 `Data` 的理由。
- 直接调用 `send_text`、`send_voice` 或任何渠道发送。
- 执行 shell、代码、学习、技能内化或主动消息任务。

## 8. 工具边界

优先复用 DSH 原生文件工具，不为日记另造一套模型可见的 `write_diary` 黑箱。

第一版建议只开放完成任务所需的：

- `read`
- `write`
- `edit`
- `glob`
- `grep`
- 作用域 `pass`

所有文件工具使用与主意识同等级别的规范化路径、真实路径、符号链接、版本和大小检查，但允许根收紧到本 session 的 `diary/` 与 `notes/`。

这些是现有 DSH 工具的复用，不表示当前占位已经注册。若实施时发现需要新增模型工具，必须先在实施文档中补全工具输入、输出、必填性、空值、默认值、校验、权限与错误 Schema。

## 9. 心跳、休息与唤醒在记忆 session 中的表现

### 常规心跳

- 只检查是否有新来源和待处理工作。
- 没有新工作时，不调用模型。
- 有待处理工作且当前 `awake`、空闲、资源允许时，启动一轮。
- 一轮结束后可以写日记、写笔记或 `pass`，不强制输出篇数。

### 休息

- 常规心跳不再唤醒模型。
- 新事件继续保留，游标不推进。
- 已有日记和笔记不删除、不自动整理。
- 状态重启后仍保留。

### 唤醒

- 明确唤醒后按原游标和批次预算继续，不跳过休息期间的经历。
- 不一次性并发补写所有日期，不制造日记写入风暴。
- 人工唤醒必须留下操作记录；她以后若可以请求休息或唤醒，另定授权工具与 Schema。

## 10. 一轮的最小因果记录

```text
主意识来源事件及版本
→ 记忆 session 的来源批次与游标
→ 实际模型请求
→ 她的思考、选择或 pass
→ read / write / edit 等真实工具调用
→ 文件结果与日记 entryId
→ 游标推进或保留原因
```

这条链只证明实际发生了什么，不把她的日记自动提升为客观事实，也不把来源事件对她的影响简化成单一因果标签。

## 11. 内部元数据草案

以下不是模型工具 Schema，只是未来工程记录的最低形状：

```ts
interface DiaryEntryMeta {
  entryId: string
  revision: number
  actor: string
  sessionId: string
  turnRef: string
  requestRef: string
  toolCallRef: string
  writtenAt: string
  sourceRefs: Array<{
    sessionId: string
    eventId: string
    revision: number
    contentHash: string
  }>
  supersedes?: string
}
```

`sourceRefs` 指向原始活动，不要求把整段私密来源复制进日记元数据。修改后的日记保留原版本，`supersedes` 只表示修订关系，不证明新解释必然更正确。

## 12. 第一版明确不做

- 不自动总结主意识 Compact。
- 不自动提取事实、偏好、关系或人格结论。
- 不自动更新主意识长期记忆。
- 不做向量库、遗忘、学习或技能管理。
- 不主动开口，不发送日记给任何人。
- 不做跨潜意识全量共享。
- 不用固定模板批量生成看似属于她的日记。

## 13. 最小实施切片与未来验收

实施时先使用隔离来源和临时工作目录，完成以下验证后再讨论真实数据：

1. `memory` 使用独立 session 与 preset，主意识提示词和历史不受污染。
2. 空队列不调用模型；同一 session 不发生重入。
3. 日记确实来自该记忆 session 的模型活动，并能追到具体来源和工具调用。
4. 她选择 `pass` 时不产生日记，也不被误记为模型失败。
5. 休息期间无模型轮、无游标推进，唤醒后来源连续。
6. 模型失败、写入失败、重启和重复事件不会造成重复日记或游标跳跃。
7. 文件工具无法写入主意识提示词、其他 session 或工作区外路径。
8. 旧日记不会被静默覆盖，修订具有版本关系。
9. 潜意识故障不阻塞主意识回复，宿主卸载后没有遗留任务。

通过隔离验收以后，再决定是否接入真实主意识投影和写真实日记；两个阶段不能合并宣称完成。
